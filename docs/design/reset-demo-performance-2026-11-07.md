## Build 22：粒子减量与递补交接

用户报告 Build 21 略有改善但仍在消散/递补重叠处卡顿。源码检查发现递补层仍使用大面积 SwiftUI mask；原生动画关键帧生成的 400 次热启动 P95 约 0.0237 ms，没有证据表明它本身耗尽帧预算。这一测量不含 SwiftUI 布局与最终系统合成。

本批将粒子从 24,240 减为 12,155，按新网格均匀铺满原卡面（颗粒约大 41%），保持漂移参数、1.7 秒时长及递补时机。递补从 393.29×408 pt 的整块透明画布缩到 237.29×160 pt，保留足够阴影与回弹边距；移除外层 SwiftUI mask，在原生宿主使用 CAGradientLayer 维持相同的下缘 6 pt 渐隐。页间飞行自动移除此专用 mask。

真实卡面、2× 离屏画布、20 帧预热 + 408 帧采样，先旧/新、再新/旧顺序：

| 指标 | Build 21 | Build 22 |
|---|---:|---:|
| 粒子数 | 24,240 | 12,155 |
| GPU P95，第 1 轮 | 0.216 ms | 0.114 ms |
| GPU P95，第 2 轮 | 0.201 ms | 0.120 ms |
| 原生递补启动 CPU P95（400 次） | 0.0237 ms | 0.0254 ms |
| 递补画布面积 | 160,462 pt² | 37,966 pt² |

GPU P95 降低约 40–47%，递补画布约减 76.3%；不据此声称真实掉帧已消除，系统合成/显示同步未包含在基准里。45 项隔离检查通过，原生 mask 布局/切回页间飞行和首帧完整性有回归覆盖。用户实际流畅度仍待复测，Demo 保持且未消费真实卡。

证据 `.build/reset-overlap-092b22/`，运行包见 [Handoff](../../HANDOFF.md)。

## Build 21：扩大画布后的卡顿排查

Build 20 用户报告明显卡顿并怀疑边缘渐隐。生产粒子画布在 2× 离屏目标下由 623×560 增为 787×816（约 1.84 倍）；Metal NSViewRepresentable 外层新增 SwiftUI `.mask`。这是明确的渲染路径变化，但此次未测到实际 WindowServer 合成耗时或屏幕掉帧率，不能直接认定遮罩为全部根因。两秒只读采样未捕获 `IslandResetDustHost`，不能用其他活动 renderer 的样本解释这次卡顿。

同机、真实卡面纹理、24,240 粒子，20 帧预热后统计 408 帧，顺序及反序各一轮：

| 离屏变体 | GPU P95 第 1 轮 / 第 2 轮（ms） |
|---|---:|
| Build 19 原画布与 shader | 0.140 / 0.136 |
| Build 20 扩大画布与边缘渐隐 | 0.142 / 0.158 |
| Build 20 关闭 shader 边缘渐隐 | 0.177 / 0.149 |
| Build 21 顶部渐隐合并至 shader、裁去下方空白 | — / 0.144 |

关闭渐隐计算没有稳定优势，不能将明显卡顿归因于几个渐隐公式；同样不能将约 0.01 ms 波动包装成整体帧率收益。所有离屏变体均远低于 120 Hz 的 8.33 ms 帧预算，此基准不包含 SwiftUI 遮罩、WindowServer、实际 drawable 等待或呈现同步。

本批移除粒子外面的 SwiftUI 遮罩，将同一顶部位置与 28 pt 线性透明度带作为 uniform 传入粒子 shader，一次输出最终透明度。保留独立粒子覆盖层，避免重新落回 ScrollView 硬裁切。粒子画布下沿只留 8 pt 安全区，2× 目标从 787×816 缩到 787×544，减少 33.3% 像素；递补仍用原对称画布，单独定位确保卡面对齐。

45 项隔离检查通过；GPU 读回覆盖渐隐起点/中间/终点透明度与四边无亮线，生产尺寸扩散探针仍为左 46、右 32、上 99 pt。粒子数量、漂移、生命期、显示同步请求、提前递补均未改变。Demo 保持，两张卡；未消费真实重置卡。实际流畅度待用户复测。

证据：`.build/reset-perf-092b21/`，运行包见 [Handoff](../../HANDOFF.md)。

## 实测与边界

Apple M1 Ultra，主屏报告最高 120 Hz。真实卡面资源，623 × 560 像素离屏目标，24,240 个粒子；每次预热 20 帧，统计后续 408 帧。生产 shader 与粒子参数未改变。

| 指标 | 优化前基准 | 复测 |
|---|---:|---:|
| CPU 编码/提交 P95 | 0.018 ms | 0.021 ms |
| GPU 命令 P95 | 0.136 ms | 0.215 ms |
| 离屏提交到完成 P95 | 0.498 ms | 0.718 ms |
| 首次卡面绘制与纹理加载 | 21.24 ms | 19.31 ms |
| 100 次共享资源命中 P95 | 无跨宿主缓存 | 0.00033 ms |

前次首个 shader/pipeline 编译调用约 284.85 ms，发生在主线程资源准备路径；随后同进程编译调用降至 0.08–0.19 ms。复测进程首编译约 1.49 ms，但 Metal 驱动缓存已热，**不能将这一下降归因于本批优化**。本批可确认的改变是编译与纹理上传在后台执行，页面宿主复建复用同一份对象，不重复创建。

GPU 数值有波动，复测并没有证明单帧 shader 变快；两轮均明显低于 120 Hz 的 8.33 ms 帧预算，因此不据此减少粒子或改画质。该离屏测试不包含 WindowServer、玻璃合成、真实 drawable 等待和整个界面布局，不能等同实际动画 FPS 或掉帧率。

3 秒运行进程采样未捕获重置粒子播放，包含其他活动特效与正常 UI 工作，不能用于证明重置卡顿的根因。证据：`.build/reset-performance-092b11-sample.txt`；基准源码、JSON 和定向检查：`.build/reset-performance-092b12/`。

## 已实施

- 原粒子使用 MTKView 固定 60 fps 定时刷新；检测到的主屏支持 120 Hz。改为 macOS 14+ 的视图绑定 CADisplayLink，请求 30–120 Hz、偏好 120 Hz，由系统依据实际所在屏幕及电源条件调度；保持 MTKView 自带定时器暂停，避免双重驱动。尚未测量用户实际屏幕上的呈现 FPS。
- 仅单次消散活跃且可见时创建刷新链；完成、隐藏、离窗、减少动态和卸载时失效。代理弱引用宿主，避免 run loop 强引用造成不可见渲染泄漏。
- 卡面 AppKit 快照仍在主线程首次创建；shader 编译、pipeline 创建和纹理上传移到后台任务。跨宿主共享不可变 GPU 资源与队列，并发请求复用同一个准备任务；等待期间不启动渲染，资源就绪后只在当前仍可播放时启动。
- 保留三帧在途上限、原始 RGBA8 纹理、24,240 粒子、1.7 秒消散、1.15 秒递补触发、0.48 秒回弹与下缘文字避让，未修改 shader 数学或粒子密度。
- 空状态中央图标由托盘修正为数学字符 ∅，保持 45% 不透明度、无扫光和无悬停倾斜；每次重启 Demo 补满 5 张。
