### 2.2 三档能力呈现（建议，C01）

| 档位 | 可显示 | 可操作 | 界面结果 |
|---|---|---|---|
| 观察 | 来源可靠的任务状态、Token、可用元信息 | 展开、选卡、筛选、查看来源 | 待确认显示“请在 Codex 处理”，不放一个永远点不动的批准按钮 |

能力按**连接、任务、请求类型**分别判断。某个命令请求可以应答，不代表表单/验证也可以。未知权限不按可应答处理。独立启动一个新的 App Server，不能作为已接管现有桌面会话的证明。

### 2.3 真正开放按钮前必须具备的条件（建议，C02）

1. 确定连接来自哪个主机、账号/工作区和服务实例，能够关联真实 thread、turn、item。
2. 收到原始请求 ID 和完整语义；请求尚未被解决、替换或撤回。
3. 明确协议版本、可用 decisions、字段含义；未知字段不被任意解释为批准。
4. 证明响应由拥有该待决请求的服务处理；跨客户端转交行为需有明确支持。
5. 能观察请求清除/解决以及后续任务事件，区分发送成功、请求解决、执行成功。
6. 能处理桌面先应答、重连、超时、乱序与重复点击。

本轮不执行上述真实通信验证；这是将来接入时的准入条件，不是本次已通过的检查。

## 3. 数据对象、归属与可信度

### 3.1 对象边界（建议，T01）

| 对象 | 用途 | 身份规则 |
|---|---|---|
| 来源连接 | 区分本机/远程、账号、服务代次 | connection ID + 服务实例/epoch；不能只用端口或 PID |
| 会话 / 任务卡片 | 一个用户可辨认的 Codex 聊天 | 来源命名空间 + threadId；改标题、目录、模型均不新建卡片 |
| 轮次 | 用户发起的一轮工作 | threadId + turnId；新一轮重置本轮状态，不重置会话累计 Token |
| 工具 / 内容项 | 命令、文件修改、公开回复等 | turnId + itemId；同名工具可并行，不能按工具名覆盖 |
| 待决请求 | 一个需回答或授权的请求 | 来源代次 + 原始 requestId（保留数字/字符串类型）+ threadId；turnId 可缺时不能捏造 |
| 草稿 | 问题答案、表单、范围选择 | 绑定上述请求身份和内容修订；不能仅绑定选中卡片 |
| 界面选择 | 用户正在查看哪个任务 | 独立于 Codex 前台窗口，也独立于最新事件来源 |

原始 ID 只用于可靠路由；诊断可用哈希，不能把显示标题当标识。

### 3.2 任务准入、排序与保留（建议，T02～T06）

| 编号 | 情况 | 规则 |
|---|---|---|
| T02 | 刚启动 / 重连 | 读取当前范围内真实活动和真实待处理请求；历史记录仅补充已知卡片，不把旧“等待”当新请求重放 |
| T03 | 新任务进入 | 首期收纳本机当前连接中可识别的用户任务；不要把所有历史聊天加载到灵动岛 |
| T04 | 子代理 / 内部审查 | 默认归入父任务轨迹，不重复计会话和 Token；内部 Guardian 等隐藏。缺父子关系时不凭标题拼接 |
| T05 | 顺序 | 首期保留已显示任务的稳定顺序，新任务追加；状态更新、计时、Token、标题变化不重排 |
| T06 | 完成保留 | 建议保留本批结束任务供查看，下一批真实任务开始后清理旧的已结束卡片；正在查看的结果暂保留到离开详情。待确认、失败未读、断线未知项不被静默当“完成”清走 |

这里的稳定追加和保留策略是生产建议，不等同旧生产逻辑；旧实现存在“选中行后插入”和完成组收起/隐藏计时，需审核后有意取舍，不能无意识继承。

列表常规可见四行、其余滚动；总任务数不是四条上限。大数量使用虚拟化，不丢弃后台真实请求。保留条数/时间上限要可配置并给出“还有 N 条”入口，不能因缓存上限让待确认任务消失。

### 3.3 来源优先级与数据更新（建议，T07）

- 同一服务、同一轮次的明确最终事件优先于本地时间推测；用可用序号/版本/事件身份去重和判旧。
- 实时 App Server、Hook、本地 rollout 是不同证据源。只有同一任务/轮次能确切关联时才合并，不能仅凭时间接近。
- 旧 Hook 的“工作中”不得覆盖已经收到的真实完成；旧轮次错误不得盖过新轮次。
- 同一来源内校验事件先后；不得把 Socket 接收时间与本地持久记录的发生时间直接比较，导致当前轮可信完成被丢弃。0.7.3 已补充这一晚到完成反例的冒烟，证据见开发交付记录。
- 断线后保留最后已知状态并标注过期。没有事件不等于空闲，也不等于完成。
- 同一会话来自两条来源时合并显示，不重复累计 Token；没有可靠去重依据时明确来源差异。
- 内容追加按 item 顺序累积，最终 item 替换该项的暂态内容；不要把最终文本再追加一次。

## 4. 状态分类与显示优先级

### 4.1 状态必须有可说明的来源（建议，S01）

| 状态 | 进入依据 | 卡片第二行 | 详情重点 | 离开依据 |
|---|---|---|---|---|
| 排队 | 来源明确表明已提交但尚未开始 | 排队中 · 来源队列说明（有则显示） | 当前提交信息 | 真实开始 / 撤销 |
| 思考 | 当前轮活动，未处于执行/待处理阶段；不猜内部推理 | 思考中 · 最近公开进展，缺失则只显示状态 | 公开 commentary，或“暂无公开进展” | 工具开始 / 等待 / 终态 |
| 执行 | 实际工具 item 处于进行中 | 具体工具名，如 exec、apply_patch；详情取真实动作 | 命令、路径、公开输出或工具参数 | item 结束或更高优先级状态 |
| 整理上下文 | 真实 contextCompaction 开始或可信来源明确状态 | 整理上下文 · 来源提供的说明 | 明确是在压缩上下文，不伪装完成 | 对应压缩完成；随后恢复本轮状态 |
| 等待批准 | 存在真实、未解决的授权请求 | 等待确认（橙黄色）· 简短原因 | 第 10 节类型化页面 | 请求解决/撤回；不靠用户点按钮立刻切走 |
| 等待回答 | 真实用户问题且来源表明会等待回答 | 等待回答（橙黄色）· 问题摘要 | 问题和选项 | 回答解决/撤回 |
| 有问题待答、仍在运行 | 来源明确是异步非阻塞提问 | 保留真实运行状态；附“有问题待答”标识 | 提问与后续运行可同时存在 | 问题解决，或来源取消 |
| 等待外部处理 | 授权页面、原生验证等需要离开岛内 | 等待授权 / 需要验证 | 服务/目标与下一步 | 来源确认结果，不根据切回窗口判断 |
| 已完成 | 当前轮明确 completed | 已完成（绿色）· 完成详情白色 | 原始完成回复、成果与可用操作 | 新轮次 |
| 已中断 | 当前轮明确 interrupted 或可信停止事件 | 已中断（灰色）· 原因 | 最后进展、未完成项 | 新轮次 |
| 失败 | 当前轮明确 failed | 失败（红色）· 原始错误摘要 | 错误、失败工具、可用输出 | 新轮次或真实恢复 |
| 状态未知 / 连接中断 | 观察链路失效 | 保留最后状态并附断线/更新时间 | 恢复说明、可用历史 | 成功重连并重新校准 |

**工具失败不等于整个任务失败。** 某条命令 exit 非 0 后 Codex 可能继续修复；只在工具详情标失败，任务以轮次状态为准。拒绝一个操作也不等于任务已中断，禁止沿用 Demo 简化的“拒绝即取消整个任务”作为生产结论。

### 4.2 冲突处理与统计（建议，S02～S04）

- 同轮最终 completed/interrupted/failed 结束其活动状态并使旧请求失效；若仍收到相冲突的请求，先校准，不能同时提供旧批准。
- 活动轮有**真实阻塞请求**时，卡片主状态优先提示待处理；并行工具仍可在详情显示，不宣称全部停住。
- 无阻塞请求时，优先真实压缩状态，再具体执行，再一般活动。并行执行显示最近发生变化的有效动作，详情注明“另有 N 项执行中”。
- 连接状态是覆盖层，不覆写业务结果。已确认完成的历史卡片断线后仍可显示完成，但不能给出实时承诺。
- 页脚状态数以每张卡片的一个主状态分组；同一卡片不重复计入思考和执行。非阻塞待答数独立提示。
- 顶部“待确认 N”建议表示**仍有待处理事项的会话数**；请求总数在筛选页显示，例如“2 个会话 · 3 项待处理”。不得把两个口径混为一谈。

## 6. 收起布局与屏幕适配

### 6.1 显示区域（固定）

- 无物理刘海：340 × 30 pt 基准，左侧 Ripple Glow、当前任务动作摘要，右侧会话统计/待确认。动态内容与统计之间保留 16 pt，文字在独立裁剪区单向滚动。
- 有物理刘海：使用屏幕公开 safe/auxiliary 区域计算，收起宽度按当前实现由硬件遮挡宽加两翼组成；左右翼对称，**硬件中央区域不放任何文本、按钮或滚动内容**。
- 展开宽度以 680 pt 为基准，并受屏幕可用宽度及真实刘海约束；不是不顾显示器宽度强制 680。
- 虚拟刘海 96 × 30 pt 只是现有 DEBUG 演示能力，不进入生产默认 UI。
- 顶部贴屏幕边缘；普通最大化窗口不能遮住下缘。窗口在视觉岛体和必要控件以外的透明区域不拦截点击，外围辉光不能扩大点击区域。
- 不新增“刘海中部滚动区”去覆盖摄像头。屏幕缩放/切换改变时重新计算几何，不用机器型号硬编码。

### 6.2 收起内容优先级（建议，L01）

| 场景 | 主内容 | 右侧 |
|---|---|---|
| 普通运行 | 当前选中任务的具体操作/公开进展 | 会话数；空间允许时保留该会话 Token |

| 断线 | “连接中断”或最后状态的过期标识 | 不显示虚假的实时正常指示 |

缩窄时先移除非必要 Token 等辅助信息，保留动作与待处理入口；不把状态统计挤进滚动文字。完整信息在展开态可见。具体紧凑取舍列入 D05，不能改动固定 Demo 后再请审核。

### 6.3 多屏、全屏与锁屏（建议，L02）

- 首期只在一个指定屏幕显示，默认系统主屏；拔出后回退主屏。不要每次鼠标移屏就搬动窗口。
- 当前屏幕的刘海、安全区、Dock、缩放倍率各自计算；插拔后夹紧尺寸并恢复可见位置。
- 普通应用全屏/Space 切换保持同一展示意图，受系统能力约束；不承诺覆盖锁屏、授权安全层或其他系统专属界面。
- 锁屏/睡眠隐藏敏感内容并暂停动画；唤醒后先校准状态，旧批准按钮暂不可用。

### 8.1 模型短名与静态显示

沿用如“6 Astra · High”的紧凑格式，原始完整名称放 Tooltip 与辅助功能文本。短名映射需按真实模型 ID 有版本地维护，不按字符串随意猜品牌/档位。

模型与推理强度必须完整静态显示。遇到未来未知长名称，建议先使用来源短显示名，再按统一可审查规则缩写；确实放不下时让元信息区换行并按需增高该卡，而不是滚动、裁掉关键档位或缩至难读。**这个极端布局回退尚未实现，需要 D06 审核，普通卡仍保持 60 pt。**

### 8.2 时间与 Token 不互相冒充

- 列表时长显示“小于 1 分钟、Xm、Xh Ym”等紧凑单位；Tooltip 说明“本轮历时，含等待”。长时间等待不能误导为持续消耗算力。
- 没有完整时序时，不计算“纯思考耗时”“纯执行耗时”。机器休眠、重连用来源时间校准，不能累计重复。
- 卡片 Token 是会话累计；本轮增量仅在有可靠轮次起始值/完整轮次用量时单独显示，禁止差分未知基线。
- 上下文占用与累计 Token 是两个指标。压缩可能降低上下文占用，不代表过去消耗被退回。
- 多任务页脚不增加未经去重的 Token 总和；子代理可能被父线程统计包含，不能双算。
- Token 不直接换算剩余额度、金额或完成百分比；额度与用量各有独立来源。

### 8.3 展开顶栏额度摘要（建议，F10）

固定样式是百分比圆环 + 白色“额度剩余”；普通圆环白灰，警告沿用正式额度组件既有阈值，避免另造一套颜色阈值。

建议：在当前账号/可确认适用的额度桶内，从有效窗口中取剩余最少的一项做摘要，点击展示窗口名称、剩余、重置时间和更新时间。多桶归属不明确时显示“查看额度”，不把不相关模型桶的最低值冒充当前任务额度。额度来源结构参考[官方额度字段说明](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)。

显示刷新按真实推送/已有额度刷新机制，不跟随每帧动效轮询。断线保留最后数据但标过期。真实额度重置仍不调用消费接口。

## 9. 普通详情、公开轨迹与进度特效

### 9.1 内容边界（固定 + 建议，E01）

这里的“思考与执行轨迹”只指**Codex 已公开显示的进展消息、工具操作、结果、计划和错误**。不读取/展示原始内部 reasoning/content，不凭状态、Token 或耗时编造推理过程；没有公开内容就明确空态。

固定 Demo 的原文来自历史公开夹具，生产不能继续把这些夹具作为真实任务内容。接入时移除“原文参考”演示来源标记，改为准确的实时/历史来源及时间；若仍是缓存则清楚标注。

| 状态 | 默认展开内容 | 次级内容 | 不重复的内容 |
|---|---|---|---|
| 思考 | 最近公开进展 | 较早公开记录、真实计划 | 不再重复卡片标题/状态/Token 三遍 |
| 执行 | 最近公开进展 + 当前工具 | 命令/参数/实时可用输出、并行工具 | 不自编“三步正在做什么” |
| 完成 | 原始完成回复、成果链接/文件（来源提供时） | 最近工具、较早记录、可复制原文 | 不将普通工具成功当作任务完成总结 |
| 失败 | 当前轮真实错误；相关失败工具和退出码 | 可用输出与之前进展 | 不笼统替换成“出了点问题” |
| 中断 | “已中断”及最后公开进展 | 未完成的工具/计划，跳回任务 | 不显示成功勾，不伪造最终回复 |
| 待处理 | 独立确认页，见第 10 节 | 返回列表后仍可见待处理标识 | 不在卡片下方再嵌一套重复确认 |

### 9.2 原文完整性与加载（建议，E02～E05）

- 原文内容不自动翻译、改写或拼成新的 AI 总结；界面标签可中英切换。
- 新到的 streaming 文本可节流合并显示，但最终以 item 完结内容为准，避免字符重复和反复跳高。
- 默认突出最近消息/工具，旧记录折叠；Demo 的八条保留上限不能变成生产无说明丢弃历史的规则。
- 首期建议保留最多 200 条轻量索引、2 MiB 文本缓存；展开时按需读取更多。大输出显示“已加载部分 / 加载更多 / 在 Codex 查看”。这些是待实现预算，不是现有测量结果。
- 路径、命令、差异保持可读换行；复制得到原始字符串，不加入用于排版的换行或省略号。
- 来源本就截断必须写“来源仅提供部分内容”；本地折叠与来源缺失分开，不能用“展开全部”承诺不存在的内容。
- 生成图片、音频、附件、交互式 MCP 资源等首期显示来源元信息与打开入口；不把任意资源 HTML/脚本直接执行在岛里。
- 完成卡中的“在 Codex 查看”只导航，不触发继续执行；不提供未经授权的“自动重试任务”。

### 9.3 量子噪点与真实进度（固定效果契约 + 建议）

当前效果契约：开始在 1% 等待 4 秒识别结构化计划；有计划按完成步骤与进行中权重计算、运行中上限 95%；没有计划则使用单步骤估算、上限 50%；只有可信完成事件才进入 100%。依据：[既有进度效果契约](../specs/PROGRESS_EFFECT_ADAPTATION.md)。

生产规则：

- 噪点范围保留上述表现契约，但它不是剩余时间或精确百分比。无计划时不用数字声称“完成 50%”，Tooltip 说明“活动指示 / 估算进度”。
- 计划增加/调整允许真实进度重新校准；不为视觉一直向前而篡改计划状态。
- 待确认、压缩、错误都不能靠流逝时间补到 100%。请求被拒绝也不播放完成效果。
- 全部任务状态更新不创建多个重复 Metal 宿主；只有当前选中卡片使用量子噪点。
- 3 秒共用相位仅同步待确认呼吸，不让所有状态都变成橙色。外围辉光最低 0，等待卡噪点最低 65%；文字与黑底不闪烁。
- 任何尚有效的待确认事项都可保留整岛辉光，即使用户返回列表/收起。全部清除后去掉辉光，不留残影。
- Reduce Motion/暂停显示静态提示，离屏停止渲染，重新出现接当前相位；不从每秒更新重新起拍。

## 10. 待确认页面：公共规则与十类专用 UI

### 10.1 公共骨架（固定，A00）

1. 岛内顶栏显示橙黄色“待确认”或更具体待答状态，提供返回列表、收起；不弹出另一层独立审批窗口。
2. 顶部直接复用当前来源任务的**选中卡片**：标题、模型/推理、来源、时长、Token、量子噪点。该卡片在确认页只作身份展示，不点击后再展开另一个详情。
3. 正文按真实类型布局。短请求自然展开，长请求可扩展至屏幕可用底边并保留 30 pt 效果余量。
4. 只有超过可用高度才让正文内部滚动；操作按钮留在正文视口外且位于同一岛内。来源卡随正文滚动，保留现有做法，不强行钉顶。
5. 三个操作均为实体按钮：取消深灰、拒绝红色、通过白底黑字；42 pt 高、10 pt 圆角、8 pt 间隔。
6. 只布局实际存在的操作：一个满宽、两个等宽、三个按取消/拒绝/通过 3:3:4；没有占位空洞，没有通用“更多选择”菜单。
7. 额外批准范围/规则直接放正文，选中只修改草稿，按主按钮才提交。

### 10.2 A01 命令执行批准

**识别：** item/commandExecution/requestApproval，且没有更具体的网络/终端输入语义；核实为官方已有类型。

**显示：**

- 标题描述“允许执行此命令”；保留工具原始命令、实际工作目录、请求原因。
- 命令放等宽终端块，不只显示一个“exec”；多行 shell、引号、管道和参数完整可展开/复制。
- 请求包含额外网络/文件权限时按实际字段列出，不自行宣称“仅影响当前项目”。
- 可记住规则时，直接显示将保存的命令前缀/规则范围。规则与这一次完整命令不同，应明确区别。

**操作：**

- 正文显示协议允许的批准范围：允许一次、本会话、批准并记住规则等。
- 主按钮随所选范围改文案，如“允许本次执行”“允许并记住规则”，不能始终显示“允许一次”。
- 拒绝只拒绝该操作；取消的含义按该版本协议显示，不能和“返回列表”混用。
- 若请求提供 availableDecisions，严格采用其集合；缺失时只有版本适配器确认了默认集合才可显示。未知版本不沿用 Demo 全选项兜底。
- 提交成功后等服务状态，不能立即写“命令执行成功”。

### 10.3 A02 向运行终端输入

**识别：** 固定 Demo 使用命令批准下的 kind=writeStdin、关联审批字段；该细分必须按目标版本 schema 再核对，本次官方概览未完整规定这些字段。

**显示：**

- 当前运行的原命令、会话/进程标识（有则显示）、拟发送内容。
- 输入单独展示，换行、回车、控制字符用可识别形式说明，例如“y + 换行”；不能只写“继续”。
- 空输入若只是轮询，不应伪装成会更改终端状态的批准。
- 敏感输入按原始协议标记遮蔽；不在卡片滚动显示。

**操作：** “允许发送”及真实支持的拒绝/取消。首期不让用户在这里随意改发一段命令。目标进程已退出或请求失效时停止提交。不能另开一个终端重新执行来模拟“批准输入”。

### 10.4 A03 文件修改批准

**识别：** item/fileChange/requestApproval；用同 itemId 关联 fileChange 上下文。

**显示：**

- 文件数与新增/修改/删除/重命名类型，逐个显示路径和差异。
- 顶部汇总，文件区可折叠；长 diff 使用内部内容披露，保留删除/新增区分。
- grantRoot 如有，明确授权根目录；不能当成此次真实修改文件的完整列表。
- 请求本身可能不含 diff，必须从已关联的 item 取得，不能拿另一个任务的最近 diff 来补齐。

**操作：** 真实允许一次/会话范围、拒绝/取消。若缺失用户作决定所需的文件内容或差异，提供“在 Codex 查看并处理”；不把缺失差异当“无变更”。首期不自造逐文件批准或勾选子集提交，除非该协议确实支持。

### 10.5 A04 网络访问批准

**识别：** command approval 中存在 networkApprovalContext；核实为官方明确区分的场景。

**显示：**

- 目标域名、协议及端口（有则显示）；不要用普通 shell 命令作主要内容。
- 原因和相关工具上下文；缺少字段标未知，不省略到无法辨认目标。
- 服务可能将同目的地的多个请求合为一次批准；只展示服务确定的合并范围，客户端不自行把不同端口合并。

**操作：** 可用的一次允许、拒绝，以及真实协议提供的持久允许/阻止规则。持久化规则在正文显式选择，明确“以后对此目标生效”；初始不选记住。具体网络规则响应结构仍须按目标版本 schema 校准，不能只根据按钮文字拼 JSON。

拒绝并记住阻止规则后不能显示“已允许，继续执行”。真实任务可能另寻路径，仍由后续事件决定。

### 10.6 A05 文件系统 / 网络权限范围

**识别：** item/permissions/requestApproval；核实为官方已有类型。

**显示：**

- 请求用途、执行环境、工作目录；读、写、网络按组展示。
- 每一授权项可以辨认完整路径/域名与权限；“读”不冒充“写”，“目录”不缩成不明文件名。
- 正文显示期限：仅本轮 / 本会话，含义独立于永久系统权限。

**操作：**

- 仅能授予请求中的子集，不能增加额外根目录或更宽范围。
- 建议默认仅本轮、各项未选；用户显式选项后“授予所选权限”。是否默认勾选全部见 D09。
- “不授予”发送空授权集合，而非伪造一个普通 decline。
- 只实现协议支持的期限；会话许可不是永久许可。零选择时主操作不可用，但保留明确的不授予入口。

### 10.7 A06 第三方工具 / 连接器操作

**识别：** 用户输入请求关联到可信的 mcpToolCall 上下文，而不是任务标题中出现“文档”就判为连接器。官方说明此类审批可以通过用户输入问题承载。

**显示：**

- 服务/应用名、工具名、操作对象。
- 参数用键值对展示，路径、标题、正文等长参数可展开；例如更新文档应展示哪篇文档、改什么。
- 有原始影响说明/危险注解就如实展示；没有时说“来源未提供影响说明”，不自己保证可恢复或安全。
- 问题选项按来源原顺序完整保留；界面可以解释 Accept/Decline/Cancel，但回传仍是原始答案。

**操作：** 选择答案 → 提交选择；不能把这些选项全部硬翻成命令批准 decision。拒绝/取消相关工具后也不直接给整个任务标“已取消”；该工具结果与任务结果分开。

### 10.8 A07 问题选择 / 自由输入

**识别：** item/tool/requestUserInput，且不需要第三方工具专用上下文。

**显示：**

- 完整问题、简短标题/编号、选项标题与描述；多题显示已回答数量。
- 选项保持来源顺序，推荐项可标记“推荐”但不能代表已经提交。
- 来源允许其他答案时提供输入框；没有选项时直接自由输入；秘密字段使用安全输入。
- 首期依据当前可证实结构按单选适配，不自行把回答数组理解为任意多选。明确支持多选的类型才用多选控件。

**操作：**

- 选中不自动提交；所有必答问题合法后提交。
- 无真实取消/拒绝语义时只显示提交按钮（满宽）及顶栏返回，不伪造取消回传。
- 非阻塞问题标“可继续运行，等待你的回答”，不能误标整任务停住。
- 请求若带 autoResolutionMs，按服务约定显示自动处理时间及结果；**首期不由灵动岛擅自选择默认答案自动提交**。清除事件到达后废止草稿和旧按钮。
- 服务端问题替换时按新请求处理，旧答案不自动套给文字相似的新问题。

### 10.9 A08 工具结构化表单

**识别：** mcpServer/elicitation/request 的 form / openai/form；扩展变体只有协商能力成立才接受。

**显示：**

- 服务名、请求说明、字段标签、帮助、必填标识、适合的输入控件。
- 文本、数字、整数、布尔、枚举、协议支持的数组分别呈现，不用一种文本框凑所有字段。
- 按来源显式顺序展示；没有顺序时用稳定顺序。组内字段不随输入重新排序。
- 错误就在字段旁显示，保留用户输入并定位第一个不合法字段；不能只在最底部说“失败”。
- 数字范围、字符串长度、格式和枚举依实际 schema 校验；不能假称已支持完整 JSON Schema。

**操作：** 提交表单 / 拒绝 / 取消，按协议回传 action 与带类型的 content。复杂嵌套对象、组合 schema、未知类型先回退到受支持的 Codex/MCP 界面；不能静默丢字段或把未理解内容“默认同意”。

### 10.10 A09 外部授权页面

**识别：** mcpServer/elicitation/request 的 url 模式。

**显示：**

- 服务名、授权目的、实际目标主机；“打开授权页面 → 完成后返回”两步。
- 隐藏 URL 中不适合公开显示的 token，但不能改写真实打开目标或伪造主机。
- 默认仅接受协议适配器认可的安全 URL 类型；拒绝无主机、携带明文用户名密码或未知 scheme 的跳转，给出回退说明。

**操作：**

- 第一步“打开授权页面”；用户点击才打开浏览器。
- 返回后只显示“检查/继续授权流程”，不因窗口重新获得焦点就宣布授权成功。
- 只有真实服务约定允许的结果才发送 accept；浏览器打开成功与 OAuth/身份授权成功分开。
- 协议支持时保留拒绝/取消；重新打开页面不重复发送批准。
- 固定 Demo 的“已打开 → 模拟继续”只是演示，不能直接搬到生产当授权成功判断。

### 10.11 A10 原生验证 / 未支持请求

**识别：** 账号验证事件、已知需要原生界面的能力，或无法完整理解的请求。

**显示：**

- 来源任务卡、请求原始说明、需要去哪里处理。
- 明确“需在 Codex 完成验证”或“此类型暂不支持在灵动岛操作”。
- 不嵌仿造的验证码、登录、付款或系统权限控件；不收集本应由服务商原生验证的秘密。

**操作：** 真实可用的“在 Codex 处理”或受支持跳转入口，单按钮满宽。没有可信的拒绝/取消结构就不发送猜测响应。

固定 Demo 的 openai/userVerification 是原生回退场景夹具；本次官方概览不能证明其为通用稳定 elicitation 模式，必须列入待证实。不能因为 Demo 当前给出了拒绝/取消，就认定任意未知请求都接受同一种 action 结构。

### 10.12 其他事件不强套上述十类（建议，A11）

动态工具 item/tool/call 是客户端执行请求，不天然是人工审批；登录状态、额度耗尽、服务错误、模型安全缓冲也不天然需要“允许/拒绝”。按真实语义显示连接/等待/错误/跳回入口。出现新协议类型时先可读降级，不落回“操作影响 + 拒绝 + 允许一次”的通用假 UI。

各类协议依据见[官方批准、用户输入与 elicitation 说明](https://learn.chatgpt.com/docs/app-server#approvals)；终端输入细分、网络规则扩展及原生验证仍需匹配实际安装版本的 schema。

## 11. 批准通信、请求队列与草稿生命周期

本节全部为生产建议（R01～R10）。**不在本轮实现或做真实回传验证。**

### 11.1 一次请求的状态机（R01）

| 内部状态 | 用户看到什么 | 可以做什么 | 进入下一状态的依据 |
|---|---|---|---|
| 收到 / 校验中 | 正在读取请求 | 返回；不批准 | 身份、类型、必需上下文和应答权校验完成 |
| 可处理 | 对应类型的完整 UI | 修改草稿、选择、提交合法操作 | 用户显式提交 |
| 提交中 | 原按钮位置显示“正在提交…” | 返回/收起；暂不重复提交 | 底层发送结果及服务端事件 |
| 已发送、结果待确认 | “已发送，等待 Codex 确认” | 查看；跳回核对 | 请求 resolved / 权威状态更新 |
| 请求已解决 | “已处理”或来源给出的具体结果 | 返回列表 / 处理下一项 | 服务真实确认 |
| 明确提交失败、未送达 | “未提交成功”+可理解原因 | 确认仍有效后重试 | 同一有效请求再次提交 |
| 结果未知 | “连接中断，尚未确认处理结果” | 重连/在 Codex 核对 | 重新查询或新的权威事件 |
| 已在别处处理 | “已在 Codex 处理” | 返回 | 已解决事件，且本地未完成提交 |
| 撤回 / 过期 / 被替换 | “请求已失效” | 关闭/打开当前请求 | 服务清除、轮次终止或身份变化 |

JSON-RPC response 本身不应被假设一定有一个新的“确认回包”。通过实际协议提供的 resolved、后续 item/turn 等事件建立结论。**resolved 可以意味着已回答，也可以意味着请求被清除**；若没有明确答案结果，只显示“已处理/已失效”，不能宣称“你的批准已生效”。

### 11.2 不把三种成功混为一谈（R02）

| 阶段 | 允许的说法 | 禁止的推断 |
|---|---|---|
| 数据写入连接 | 已发送 | 已批准、已执行 |
| 请求被服务接受并解决 | 已处理 / 已批准（仅结果可证实时） | 命令成功、文件已修改 |
| 对应 item 真实完成 | 此操作完成 / 失败 / 被拒绝 | 整个任务已完成 |
| 当前 turn 真实终态 | 任务完成 / 中断 / 失败 | 新一轮也完成、会话永远结束 |

批准后保持最近可信状态，直到真实事件恢复执行。UI 不能为了流畅而将任务提前切成“工作中”。

### 11.3 多请求队列（R03）

- 同一任务可有多个待处理请求；一个请求也可能解锁服务端合并的一组网络操作。
- 一个岛同时展示一个请求，标“第 1 / 3 项”，可切换；默认按到达顺序，保留正在操作的一项。
- 不因新请求到来覆盖用户输入。新增请求只更新数量与导航。
- 不提供“全部允许”，不把同名任务或同一目录的请求批量应答。
- 当前请求处理后，建议显示短反馈再进入同任务下一项；跨任务不自动跳，提供“处理下一项”入口。具体自动前进节奏见 D08。
- 去重依据完整请求身份，同一个请求重放只刷新必要字段，不清草稿、重播提醒或重复创建按钮。

### 11.4 提交防重与断线（R04～R06）

- 用户提交时立即锁定该请求的响应版本；同一请求只允许一个在途决定。连续点击、键盘连击、选择变化都不能生成第二次发送。
- 已写入连接却未确认结果的请求不能直接“重试”。先核对服务端是否仍待决、客户端是否仍有应答权。
- 明确未发送或服务明确允许重试时，才恢复重试按钮。不要在重连时批量补发历史响应。
- 关闭详情、返回、收起不撤销在途请求；退出应用不发“默认拒绝/默认同意”，也不强制结束用户的 Codex。
- 请求替换、当前轮结束、新轮开始、账号切换、服务代次变化会使原响应失效；迟到的模拟/真实回调不能修改新请求。
- 短时间没等到结果只展示延迟状态，不能按固定秒数判操作失败。建议发送后立即显反馈，约 10 秒无结果显示“仍在等待”；此阈值是 UI 提案，不是协议超时。
- 重连使用退避并限制并发。请求/队列拥塞时显示稍后重试，不循环重启 Codex 服务。

### 11.5 草稿保存（R07）

| 动作 | 普通答案 / 范围草稿 | 秘密字段 |
|---|---|---|
| 返回列表、收起、切换任务 | 同一有效请求内存保留 | 内存保留，重新展开仍遮蔽 |
| 正文滚动、界面语言变化 | 保留原始值与选中，不翻译回传值 | 保留但不入日志 |
| 明确请求内容修订 | 检查题目/字段身份；不兼容部分清除并说明 | 不自动迁移 |
| 已解决、撤回、换轮、换账号 | 清除 | 立即清除 |
| 应用退出 / 锁屏策略触发 | 默认不持久化审批草稿 | 不落盘；锁屏清除秘密字段 |

“本会话允许”这种选择只属于当前请求的草稿，不作为下一个请求的默认选项；服务端已记住的真实权限由服务负责，不靠客户端自行记忆“以后都同意”。

### 11.6 在 Codex 处理与回退（R08）

有真实、可验证的任务导航能力才跳到对应任务。若只能打开 Codex 应用，按钮文案必须为“打开 Codex”，并告知需要手动选择任务；不能假称精确定位成功。

不能为了获得应答权模拟点击桌面批准按钮、操作数据库、修改审批策略、配置全权限或自动接受系统提示。回退是清楚说明能力缺口并保留任务信息，而不是绕过原服务的确认流程。

## 12. 控件细节、键盘与可访问性

### 12.1 按钮语义（建议，K01）

| 类型 | 颜色与位置 | 精确语义 |
|---|---|---|
| 通过 / 提交 | 白底黑字，最右或单按钮满宽 | 采用当前合法草稿；文案说明执行/发送/授予/提交哪一种 |
| 拒绝 | 红底白字 | 协议允许的拒绝，不自动表示停止整个任务 |
| 取消请求 | 深灰实体按钮 | 只有协议支持才提供，和返回页面分开 |
| 返回 / 收起 / 关闭详情 | 顶栏或详情现有图标/文字入口 | 只改变页面，不触发服务端否定回应 |
| 在 Codex 处理 | 明确导航按钮 | 只导航，不宣称批准 |
| 不可用主操作 | 不透明灰色文本/背景，附可理解原因 | 缺必填、请求失效或通信不可用；不能只剩一个没有解释的灰按钮 |

选择持久拒绝规则时，负向按钮文案同样同步为“拒绝并记住规则”。没有对应协议选项时不出现这个选择。首期每页最多三个主操作，扩展范围在正文，不扩成五六个并排按钮。

### 12.2 输入与焦点（建议，K02～K04）

- Tab 顺序与视觉顺序一致：来源/返回入口 → 正文选项/输入 → 操作。键盘焦点必须可见。
- 方向键在选择组内移动；空格选择。选项选择不触发提交。
- Enter 在单行字段不默认批准整页；多行字段按输入习惯换行。建议显式 Command-Enter 才提交合法表单，旁边给提示；破坏性/持久授权仍必须聚焦对应按钮并主动操作。
- Escape 优先退出当前子控件，再返回/收起，绝不等于拒绝或取消服务请求。
- 聚焦输入、菜单或正在拖滚动条时，鼠标暂时移出不自动收起；提交中也不因 hover 状态丢页面。
- 不默认设置会抢占 Codex 快捷键的全局热键；如增加则由用户启用与配置。
- 纯 hover 展开不成为 key window；需要输入时才获取键盘焦点。退出输入/收起合理归还原窗口焦点。

### 12.3 可读性、语言与辅助功能（建议，K05）

- 中文/English 只切界面标签，不改原问题、命令、路径、工具名和答案值。
- 关键状态不仅靠颜色，还要有文字；VoiceOver 能读出任务、主状态、待处理数、选中项与按钮语义。
- 走马灯对辅助功能只暴露一份完整文本，不能把循环副本读两遍。
- 核心数字使用稳定宽度，避免 Token/时间改变时推挤标题。
- 输入错误关联字段，成功/失效/断线使用适度播报，不逐 Token 播报。
- 系统“减少动态”保留静态状态提示与所有操作；不以动画作为唯一待确认提示。
- 很窄/很短屏幕优先保证来源身份、问题及按钮可访问；滚动揭示全部内容，不能被底栏盖住。

## 13. 隐私、异常与恢复

### 13.1 内容范围（建议，P01）

| 内容 | 默认做法 |
|---|---|
| 任务标题、操作摘要 | 仅显示该连接真实可访问任务；提供隐私模式隐藏具体标题/路径 |
| 密码、令牌、秘密答案 | 遮蔽；不出现在卡片、Tooltip、普通日志、诊断导出 |
| 命令/输出/差异 | 展示来源原文；明确标记必要脱敏，不悄悄改变原始语义 |
| 缓存 | 首期公开轨迹与请求草稿默认仅内存；诊断保存元信息，不保存全文 |
| 复制 | 仅用户点击触发；密文不自动进入剪贴板 |
| 链接与文件 | 用户主动打开；验证类型和可访问范围，不自动执行命令或资源代码 |
| 账号/主机切换 | 清理旧授权与草稿命名空间；不能把 A 账号额度或请求当 B 的 |
| 日志 | 记录状态/时间/错误码/哈希标识；不记录完整命令正文、token 或请求秘密 |

生产显示任务内容超出了当前元数据订阅的范围，应在启用公开内容展示时明确告知读取范围。首期不上传这些内容到新的第三方服务，也不额外调用模型总结原文。

### 13.2 异常显示矩阵（建议，P02）

| 情况 | 显示 | 操作 / 恢复 |
|---|---|---|
| Codex 未运行 / 未找到受支持连接 | “未连接 Codex”，空闲岛可保留额度来源说明 | 打开 Codex / 查看连接说明；不自动创建一批会话 |
| 尚未登录 / 登录过期 | “需在 Codex 登录” | 导向原生登录；不在岛内保存账号凭证 |
| socket 断开 / 主机离线 | 最后状态 + “连接中断” | 暂停应答，退避恢复并重新校准 |
| 内容不可读 / 权限不足 | 保留卡片元信息，“详情暂不可用” | 在 Codex 查看；不声称无内容 |
| 未知请求类型 / schema 不支持 | 来源任务与原始说明 + 不支持原因 | 在 Codex 处理；不显示伪批准 |
| 请求已在桌面处理 | “已在 Codex 处理” | 关闭旧操作，更新计数；不报错误吓用户 |
| 任务完成时弹来旧批准 | 标失效或校准中 | 不开放旧按钮 |
| 命令失败但任务继续 | 工具显示原始失败，卡片仍按当前活动 | 继续展示后续修复轨迹 |
| 额度耗尽 / 服务限流 | 使用来源原因，区分额度窗口与暂时限流 | 展示真实重置/重试信息；不承诺自行恢复、不消费重置 |
| 自动审批被策略拦截 | 原始结果“被策略拒绝/无法在此批准” | 原生处理/说明；不伪装成人工拒绝 |
| 字段乱码 / 过大输出 | 安全渲染文本，说明截断或格式不支持 | 查看原文来源；不无限占内存 |
| 系统休眠后恢复 | “正在同步”，保留旧画面但禁旧操作 | 读取新快照与真实待决请求 |
| 窗口被系统层覆盖 | 不判定任务异常 | 维持状态；不循环抢前台或调整最高层级 |
| 应用退出重启 | 恢复展示偏好，重新核实任务和请求 | 不从磁盘审批草稿自动回传 |

## 14. 性能、资源与实现边界

以下是后续生产实施的约束与测量目标，不是本轮已实现/通过的性能结论。

### 14.1 保留现有有效结构（建议，B01）

- 保留固定原生窗口画布及 Core Animation 外壳过渡；屏幕几何改变才重算窗口，不在展开/收起每帧 resize。
- 事件接收、解析、存储与渲染分开；网络/文件 I/O 不在主线程执行。
- 使用一套真实 Task Store 与请求队列，Demo 通过独立适配器供同一展示模型；禁止生产中依赖 Demo 随机任务和模拟状态转换。
- 请求 UI 按真实类型分发；从数据解码到最终页面都带 request 身份，避免重现“场景夹具被通用确认覆盖”的问题。
- 复用现有按钮/卡片/尺寸令牌。滚动条只保留当前一套实现，不恢复多轮试验遗留的 scroller 设置、监听和吸附代码。
- 公开内容订阅应按需开启/释放，不因只是显示额度就获取所有聊天全文。连接观察退出时清理订阅与回调。
- 定时更新只服务时长/新鲜度，按显示精度刷新；文字逐帧动画留给原生合成层，不以 SwiftUI 状态驱动每个动画帧。

### 14.2 有界更新与动画（建议，B02）

- 可见任务才运行 AI 球；不可见卡片、隐藏详情、锁屏、睡眠、关闭功能停止对应渲染。
- 整岛仅一套等待辉光时钟；可见选中卡共享相位。不要每个任务各开一个长期 Timer。
- 球体沿用每轴 2× backing 的局部超采样，不能为小球锯齿把整个窗口提升采样倍率。
- 内容 delta 可按最多约 10 次/秒合并展示，终态、待确认和失效立即更新；这是候选预算，不延迟服务处理。
- 布局缓存有界，键包含内容版本、宽度、语言、屏幕可用高度；输入变化只失效受影响项。
- 对同一状态/同一播放状态的重复更新不重启 shader、动画、滚动或文本测量。
- 缓存满时淘汰可重新读取的正文，保留活动任务索引与所有有效待决请求身份；不得静默丢请求。

### 14.3 必要基准建议（B03）

| 样本 | 测什么 | 候选门槛 / 解释 |
|---|---|---|
| 1、4、12、50 个任务 | 展开/收起、连续滚动时主线程同步布局 | 目标 P95 ≤ 4 ms；记录机器、分辨率、构建类型，不凭一次数字承诺手感 |
| 单/多请求、长问题、长 diff | 高度测量、切换、输入、滚动 | 不因文本长度每帧重测；按钮区域始终可达 |
| 公开输出高频追加 | 解析队列、合并刷新、内存上限 | 无无界积压；终态/失效不被文本洪流延迟 |
| 后台运行、隐藏、睡眠恢复 | CPU/GPU 与动画宿主数量 | 停止应停资源；保留常驻状态不等于所有动画常开 |
| 多屏/缩放变化 | 几何缓存重算与触达区域 | 无卡死、负尺寸、透明区挡鼠标或失去按钮 |

只做相关基准与冒烟，不扩大完整回归或自动化视觉验收。CPU/GPU/输入延迟必须说明测量方法，离屏布局 P95 与主循环采样不能冒充 GPU 帧率或实际滚动手感。

## 16. 需要审核的产品决策

以下均为**建议默认值，尚未自动实施**。用户可只回复编号及修改意见。

| 决策 | 建议默认 | 需要确认的取舍 |
|---|---|---|
| D01 · 任务范围 | 首期只纳入本机当前连接中的用户活动/待处理任务，子代理归父任务 | 是否首期就覆盖远程/云端和历史任务？建议分期 |
| D02 · 排序与结束保留 | 稳定顺序、新任务追加；结束项保留到下一批开始，正在查看的结果暂保留 | 是否更偏向“进行中优先排序”或按时间长期保留？ |
| D03 · 无任务常驻 | 保留收起岛，显示额度/空闲状态；只在用户关闭功能或退出应用时移除 | 覆盖旧生产的自动隐藏策略，与此前常驻要求一致 |
| D04 · 图钉与选择 | 手动主任务；图钉本次运行有效；不猜 Codex 前台所选聊天 | 是否需要跨启动记忆图钉/选中任务？ |
| D05 · 收起信息 | 具体操作优先，右侧会话数+待处理；窄屏先让出 Token | 是否坚持收起态始终保留 Token，接受更少动作文字？ |
| D06 · 极端长模型 | 短名完整静态；确实放不下时元信息换行、该行增高 | 是否接受极端情形非 60 pt 卡片？不会改变常规尺寸 |
| D07 · 新待处理提醒 | 计数+整岛辉光；不强制展开、不抢焦点、不默认声音 | 是否希望空闲且未输入时自动展开？ |
| D08 · 多请求处理 | 同任务下一请求可在结果反馈后接续；跨任务手动进入 | 是否所有请求都手动“下一项”，以减少页面自动变化？ |
| D09 · 权限默认值 | 仅本轮，权限项未选；持久规则永不默认勾选 | 是否普通权限默认选中请求项？扩大范围仍必须显式选择 |
| D10 · 时长与 Token | 时长为当前轮总历时（含等待），Token 为会话累计 | 是否改为时长排除等待？这会增加时序与缺失口径要求 |
| D11 · 额度摘要 | 取明确适用桶中最紧张窗口；多桶不明时“查看额度” | 是否固定显示主窗口，让其他额度只在详情出现？ |
| D12 · 跨屏与隐私 | 单一指定屏幕，默认主屏；公开内容内存缓存，提供隐私模式 | 是否需要每屏都显示？首期建议不做多份并行交互入口 |
| D13 · 应答能力 | 按类型逐项开放；能力不明就“在 Codex 处理” | 是否接受首期“真实观察 + 原生处理”，之后补岛内应答？ |
| D14 · 问题自动处理 | 灵动岛不按默认选项自动回答；遵从服务 resolved/清除 | 即使服务提供自动解决时间，也不在本地自行挑答案 |

**建议优先审 D01、D02、D03、D07、D08、D10、D13。** 其他条目主要是边界行为，可在确定主方向后补充。固定 UI 不因本文建议而自动变化。

### 17.2 尚未证实、不能隐藏在“已支持”里的事项

- 目标桌面版本是否将完整 server request 交付给当前外部连接，以及谁拥有回答权。
- 跨客户端 resolved、请求恢复及同时应答的实际行为。

- 终端输入细分、网络规则扩展、原生验证的目标版本 schema 与 capability。
- 真实前台聊天选择事件及可靠任务跳转能力。
- 异步问题是否会阻塞任务及自动处理语义，必须来自服务明确信息。
- 多主机/账号、全屏/Space、长时间性能与实际交互体验。

官方文档是协议依据，不是这些条件的本机实测证明。后续按目标安装版本生成/读取对应 schema，只扩展已证实类型；旧版或未知类型回退。
