### 切换规则

- 开启：从已有可信任务快照初始化，按可信焦点或既定降级选择建立主岛；
  不把历史会话全部加入，不补演旧通知或完成动效，不创建模型任务。
- 关闭：偏好立即持久化，撤销多任务观察和待执行工作，使旧异步回调、事件
  合并窗口、完成收拢及动画计时失效，再恢复原单岛呈现；无需重启应用。
  分离、切换和融合中也必须能退出，不等所有任务完成，不播放「全部完成」。
- 关闭不改变 Codex 任务执行、真实完成状态、Token 或 Hook 配置。设置入口
  独立于浮岛展示，焦点识别失败或多任务布局异常时仍能操作此回退开关。
- 快速反复开关只保留最新模式，使用模式版本隔离迟到回调，不能重复注册观察、
  复活子岛、重播提醒，或让旧模式修改新模式的显示。

## 压缩状态：已确认的缺口

1. `CodexLocalRolloutLineDecoder.decodeEventMessage` 依赖

### 已确认前提：全部任务完成后才缩略

灵动岛的展开 / 缩略取决于当前跟踪任务整体，不取决于主卡当前显示哪一项。
「全部任务」指本轮已确认并纳入灵动岛的任务集合，不包括历史会话列表。

- 只要有一项未完成，整岛保持展开。思考、工作、压缩、等待确认或输入
  都属于未完成；长时间静默、鼠标移出或当前主任务完成都不能触发自动缩略。
- 主任务完成时只展示该任务回执，随后按选择规则切换；后台仍有任务就保持
  展开。后台完成只更新对应项，不启动整岛缩略或隐藏倒计时。
- 最后一项可信完成后，统一展示整体完成回执，再进入缩略态；完成回执的
  驻留时长仍待沿用现有设置验证，不自行改变已确认的过渡动效。
- 回执或缩略倒计时期间有新任务 / 新轮次加入，立即取消待执行的缩略和隐藏；
  已缩略时有新任务则展开。旧轮次计时器不得改变新任务的展示状态。
- 失败、取消、断连或状态未知不能伪称「全部完成」。这些异常如何确认收尾
  留待后续设计，当前不得仅依据「活跃数为零」自动缩略。

该前提同样适用于多任务模式下只剩一项未完成的情况。此前两张概念图中
「3 项进行中」的缩略态示意作废；右侧任务列和底部任务条均应以展开状态
承载未完成任务，缩略态只在满足整体完成条件后出现。手动收起的例外尚未
获确认，不把它作为绕过此规则的默认交互。

### 历史视觉探索：主岛与卫星球（已由上述规则取代）

以下记录保留设计演变，44 pt、槽位交换及完成汇总均不适用于当前原型。

用户关闭前两个方案的开发台后提出新方向：第一个任务沿用现有单岛；出现
后台任务时从主岛右侧以黏性分离形成小球；当前查看的会话显示大岛，其余
会话显示小球。本轮授权补全视觉方案和效果图，未授权该方向的原型或生产实现。
旧开发台已按用户要求关闭，源码与启动器保留。

**几何与层级：**主岛沿用现有进度条可见表面约 402 × 68 pt，锚点、宽度和
文字位置不因后台数量改变。卫星球直径建议 44 pt、净间距 10 pt，与主岛
垂直中心对齐，从右侧延伸；不为了居中整组而让主岛横向移动。小球使用同样
的黑色表面、轻描边和圆润轮廓，不做玻璃球或高亮立体球。仅主岛保留完整
粒子特效，后台以两字短名和轻量状态标记表达。

**状态表达：**工作用青色点，思考用紫色点，压缩用银白压缩符号，待确认用
琥珀色菱形和克制的呼吸描边，完成用绿色勾并降低强调，失败用红色感叹号，
未知用灰色问号。颜色同时配合符号，悬停 / 键盘聚焦显示完整标题与状态。
用户随后明确完成任务应聚合，完成球不长期逐个保留，按下方完成汇总规则迁移。

**出现与切换：**

- 首个任务使用现有单岛呼出。新增后台任务时从右缘鼓起、拉出凹弧连接颈、
  逐渐收细并断开成球；稳定态各球完全分离，不常驻黏性连接。
- 检测到任务与确认会话焦点是两件事：焦点仍在 A 时，A 保持主岛，B 成球；
  若用户已切到 B，则 B 成为主岛，原 A 分离为球。后台更新本身不抢焦点。
- 切换到某个已有后台会话时，该球融入主岛，原主任务分离到被选球的槽位。
  其余球位置保持不变。非相邻球交换在前景短暂经过，不挤动中间球。
- 只有外壳参与拉伸，文字与符号独立淡出 / 淡入，避免字符被液态拉长。
  分离与交换建议先以 0.4–0.6 秒探索，尚未冻结动效参数；快速连续切换
  从当前形态转向最新目标，不排队播放过时会话。
- 会话跟随能力仍需独立验证。球的点击联动也须拿到可信会话身份，不能把
  仅切换岛内显示宣称为 Codex 已切换。无可靠焦点时保留最后可信选择。

**完成汇总与灵活切换（用户补充）：**

- 当前主任务未完成时，已完成任务合并为右侧一个小号胶囊分岛，显示
  「✓ 已完成 N 项」，不再为每个已完成任务占一个球。未完成任务仍各自为球。
- 当前主任务已完成时，完成汇总融入主岛；主岛保留当前会话标题，显示
  「已完成 N 项」。N 包括当前会话，不重复计数；该数字表示完成集合大小，
  不表示全部任务都完成。此时未完成任务仍留在主岛右侧。
- 切换到运行 / 压缩 / 待确认会话时，该会话成为主岛，完成汇总重新分离成
  小号分岛。切回某个已完成会话时，汇总再次融入主岛；两种形态跟随选择，
  不把完成汇总固定在某个任务位置，也不强行切走已完成的当前会话。
- 点击完成分岛，或主岛中的完成计数，展开已完成任务列表；选择具体会话
  后进行对应的会话切换。融合 / 分离只改变呈现，不丢失每个任务的身份。
- 主任务自身完成时，它仍留在主岛并接纳已有完成汇总；不自动用另一个运行
  任务替换用户当前会话。这替代前两个原型中主任务完成即选择下一项的规则。
- 某完成任务进入新轮次时，从完成集合移出、完成数减一，按当前焦点回到
  主岛或未完成球；汇总数变为零时移除完成分岛。只统计本轮纳入的任务，
  不把历史已完成会话无限累加。Token 若保留仍只属于当前任务，不因汇总而混加。

**容量与收尾：**右侧最多三个位置，完成胶囊占一个位置。没有完成汇总时，
未完成后台超过三项显示两个任务球和 +N；完成汇总在外时，超过剩余两个位置
则显示一个任务球、+N 和完成胶囊。+N 只统计未在独立球展示的未完成任务，
完成 N 独立计数。+N 展开未完成列表，隐藏任务有待确认时同步琥珀标记。
保持任务次序，新增完成只更新汇总数，不重排其余未完成球。
仅剩一项未完成、当前主任务完成或等待确认时，均保持主岛展开。
全部任务可信完成后，完成汇总归入主岛，显示整体完成回执，再按原有缩略
动效收起。任一阶段新增任务立即取消收尾并恢复展开；失败、取消、未知
不进入“全部完成”的成功收尾。Reduce Motion 用直接布局和轻淡入替代
拉伸 / 分离过程，状态、焦点和完成门槛不变。

效果图以「单任务 → 黏性分离 → 多任务稳定态 → 会话交换 → 全部完成收拢」
关键帧展示此方向，属于形态示意；实际固定尺寸、命中区、同一时刻插值和
快速切换需在后续获授权的开发台中验证。前两个列表方案保留为比较历史。

### 最小范围与数据规则

- 一行对应一个已确认的用户任务；列表行以 session 保持稳定，当前轮次由
  `(session, turn, generation)` 区分。新轮次重置进度、Token 基线、回执与提醒。
  内部审核和子 Agent 不独立计数，关系不可靠时不展示父任务摘要。
- 复用三条既有来源，所有事件经过同一准入和去重。Hook 缺少 turn ID 时只按
  现有规则补充所属任务，不凭弱来源结束另一轮次。
- 活跃任务数 = 运行（思考/工作/压缩）+ 等待确认/输入。完成、取消、失败、
  历史记录及状态待确认项不计入活跃数；等待/失败另有待处理标记，近期完成
  可暂留列表作为回执。各任务进度独立，无计划时无百分比，不计算平均总进度。
- 启动恢复沿用新鲜事件确认门禁。找到旧日志不等于仍运行；单纯长时间静默
  也不等于完成。任务观察丢失时保留最后状态并标记待确认，停止宣称其运行。
- 默认 24 个发现候选与任务注册表的 128 项上限是采集/内存边界，不是 UI 数量。
  在有界预算内优先保留已确认运行、等待和手动关注的任务，先淘汰已结束记录；
  真正达到容量上限必须暴露覆盖不足，不能悄悄少算或显示成完成。

### 展示与主任务选择建议

建议默认保留当前主任务卡片和动效，加活跃任务数入口；点击后在同一岛内切到
最多三行的任务列表，更多项滚动。列表显示标题、状态和有依据的独立进度；
Token 等细节保留在所选任务详情，避免每行拥挤。仅一项任务时可以沿用现有
内容布局，但自动缩略必须服从上述整体完成前提。
“默认卡片 + 列表入口”与“展开态直接三行”已作为偏好问题提交用户，尚未确认；
此前直接三行的草案不是已接受的布局。几何与动效需要后续隔离原型验证。

| 触发 | 建议行为 |
|---|---|
| 用户点选任务 | 立即关注该轮，优先于自动选择；用户可恢复自动，或在该轮回执消退后自动释放关注 |
| 普通后台工具/Token/压缩事件 | 更新对应行，不抢主任务、不打乱列表顺序 |
| 新的确认请求或失败 | 增加待处理标记；自动模式可优先选尚未提示的待处理项，同级不来回切；用户正在操作列表或已手动关注时只标记 |
| 当前任务结束 | 在当前任务内显示回执，驻留后再选下一任务；其他任务未完成时整岛持续展开，不启动整岛缩略计时 |
| 后台任务结束 | 更新该行和活跃数，不用后台完成事件替换主卡或重播整个岛的完成效果 |
| 全部任务可信完成 | 从最后完成时刻进入整体完成回执，驻留后才允许缩略；后续隐藏沿用现有流程，新任务到来即取消旧计时 |

自动选择顺序建议为：有效手动关注 → 尚未提示的待处理任务 → 当前仍有效的
主任务 → 等候最久的下一任务。待处理项只在新请求/新失败到来时重新获得提示
资格，避免一个失败任务永久抢占。列表按首次进入次序稳定排列；提示标记可变，
普通事件不重排。点选仅切换灵动岛详情；跳转 Codex 指定任务不包含在首版。

只给主任务运行现有 Metal 效果；其他行使用状态点和轻量进度，避免按任务数
复制渲染器。切换时原子替换标题、状态、进度和 Token，并按身份重置效果。

### 新增会话焦点链路：近实时目标（待实测）

用户允许添加新的信息获取链路。建议增加独立的界面焦点来源，仅影响主任务
选择；运行/压缩/完成状态仍由原来的真实任务事件决定。切换到一个旧会话
不能把它重新标成正在运行，也不能仅因看到某个任务就修改其 Token 或计划。

- **事件驱动优先：**观察 Codex 应用激活、焦点窗口变化；同一窗口内部则观察
  侧栏选中项、焦点元素及必要的标题/布局变化。系统存在这些辅助功能通知，
  但目标元素可能不支持，不能把 API 存在当作当前 Codex 已可靠发出事件。
- **定位身份：**优先读取选中元素公开的稳定任务标识或任务链接（若有），转换为
  现有 session 身份；否则仅在标题与已有任务元数据唯一匹配时跟随。重名、
  标题尚未加载、不同来源的同名任务和快速跳转结果均须拒绝误匹配。
- **有限补漏：**仅在 Codex 前台、功能启用且辅助功能已授权时，对已定位的小范围
  控件以 250–500 ms 候选周期检查；事件合并后只处理最新窗口/会话版本，旧异步
  读取不得覆盖新焦点。离开 Codex 停止高频检查，无需遍历正文或截图识别。
- **延迟目标：**事件路径可将 100–300 ms 设为工程目标，轮询补漏以亚秒级为目标；
  都不是已测结果或系统保证。分别测量通知覆盖、身份匹配正确率和从界面状态
  改变到灵动岛更新的耗时，未取得稳定身份时速度达标也不算验收通过。
- **选择策略：**有效手动关注优先；自动模式下，可信前台会话优先于活动事件
  仲裁。焦点匹配失败保留既有选择并显示未跟随，不用最近输出任务冒充当前会话。

本机当前导出的 App Server schema 与 [OpenAI 官方 API 概览](https://learn.chatgpt.com/docs/app-server#api-overview)
可确认 `thread/status/changed` 是运行状态，`thread/loaded/list` 是加载集合；
本轮没有找到公开的前台会话选择订阅接口。此结论仅限所检查的公开协议，
不否认宿主内部可能维护界面路由。生产首选公开辅助功能通道，当前未依赖内部
IPC、修改宿主或注入脚本。

依据：[Apple 焦点窗口通知](https://developer.apple.com/documentation/applicationservices/kaxfocusedwindowchangednotification)、
[选中项通知](https://developer.apple.com/documentation/applicationservices/kaxselectedchildrenchangednotification)、
[通知注册及不支持情形](https://developer.apple.com/documentation/applicationservices/1462089-axobserveraddnotification)。
下一验证应使用已有会话的手动切换与有界本地元数据探针；不发消息、不创建模型
任务、不人为触发压缩。多窗口、同窗口切换、同名任务、快速连续切换和权限拒绝
都必须分别验证。本轮只有源码及文档核对，未读取当前界面树或测量延迟。

### 在现有框架内的实施边界

1. 在现有 Store 内收敛按任务保存的状态；任务准入只判归属/可信度，选择逻辑
   独立决定主任务。保留当前单任务 snapshot 作为选中任务投影，降低迁移影响。
2. 补充已活跃任务的持续观察、每任务故障状态、去重与回执/提醒截止时间；
   用统一调度处理最近截止项，避免每条更新都取消并重建所有任务的计时器。
3. 在现有 Runtime / RenderState / Panel 上增加列表投影与选择回调；共享外壳、
   标题查询连接和一个主特效，不创建第二套采集服务或每任务窗口。
4. 方案确认后先在隔离开发台验证布局、选择与结束场景，再决定生产实施；
   当前未授权多任务构建或迁入生产。
