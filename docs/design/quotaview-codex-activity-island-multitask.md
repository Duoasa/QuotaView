## MULTITASK-01. 冻结结论

多任务灵动岛采用“固定单岛 + 右侧任务列表”的任务簇，不为每个 Codex
任务创建独立卡片或系统浮窗：

- macOS 顶部继续只存在一个非激活、鼠标穿透的承载 `NSPanel`；
- 单任务时完全保持现有最大态、紧凑态和隐藏规则；
- 多任务时，单一主岛保持既有完整布局并在右侧显示任务列表；
- 两个到四个任务共用同一个固定尺寸、固定外轮廓的主岛；
- 不绘制右侧小岛、背层卡片、堆叠边缘或其他仅用于装饰的任务容器；
- 用户切换当前 Codex 任务时，直接同步主任务内容、任务列表选中态和
  Metal 状态，不对整张主岛卡片执行切换动画；
- 主任务的 Metal 球、标题、状态和操作均对应当前选中的 Codex 任务；
- 后台任务不得仅因产生普通新事件而抢走用户主动选择的主任务；
- 后台待确认与失败状态通过主岛右侧任务列表明确提示，但不强制切换
  主任务；
- 无法高置信度识别当前任务时保持原主任务，绝不猜测切换。

多任务能力的核心不是同时展示更多信息，而是让用户当前查看的 Codex
任务与灵动岛主状态保持一致，降低并行工作时的任务对应成本。

## MULTITASK-02. 名词与身份模型

### 任务

“任务”指一个能够由现有 Hook `sessionHash` 区分、并能够通过 Codex App
Server 匹配到线程元数据的 Codex 会话。

同一个 `sessionHash` 即使因界面重建或窗口变化被重复观察，也只能生成
一个任务状态。不同 `sessionHash` 必须独立保存状态、标题、时间和收起
周期。

### 原生窗口与窗口内任务

2026-08-01 的隔离验证显示，当前真实 Codex 环境只有一个标题为
`ChatGPT` 的原生 `AXStandardWindow`，多个任务主要在同一个原生窗口内部
切换。因此，正式方案不能只监听原生窗口焦点变化。

任务定位采用统一规则：

1. Codex 存在多个原生窗口时，先确定当前聚焦的标准窗口；
2. 在该窗口的主内容标题区读取当前任务标题；
3. Codex 只有一个原生窗口时，直接读取该窗口的主内容任务标题；
4. 使用任务标题与 App Server 线程元数据进行高置信度匹配；
5. 成功匹配后，以对应 `sessionHash` 作为唯一业务身份。

## MULTITASK-03. 隔离技术验证结论

本方案已使用位于系统临时目录的独立探针完成验证。探针未链接、编译或
修改 QuotaView 生产源码，验证结束后已全部删除。

### 已验证

- Codex Desktop Bundle ID 为 `com.openai.codex`；
- 当前环境可见一个标准原生窗口，窗口标题只有通用值 `ChatGPT`；
- 当前任务标题在主内容区顶部以辅助功能 `AXButton` 标题暴露；
- 侧栏任务标题与主内容区当前任务标题可以通过位置与层级区分；
- 从当前任务切换到另一真实任务后，主内容区标题同步变为目标任务
  标题；
- 恢复当前任务后，主内容区标题同步恢复；
- 主内容区标题可与 App Server `thread/list` 返回的线程名称精确匹配；
- 验证时当前标题在 `77` 个线程中只有 `1` 个精确匹配；
- 精确匹配后能够得到与现有 Hook 一致的脱敏线程身份；
- 定点读取一个已经稳定显示的当前标题约需 `57 ms`；
- 三轮真实往返、六次主标题切换的检测结果为：
  `575 / 631 / 567 / 633 / 567 / 641 ms`；
- 上述切换延迟与 Codex 自身任务视图切换同步，能够承接主任务内容与
  状态的同步更新。

### 未采用

- 仅通过 `NSWorkspace.frontmostApplication`：只能知道 Codex 是否位于前台，
  不能知道窗口内当前任务；
- 仅监听 `kAXFocusedWindowChangedNotification`：单窗口内部切换任务时不会
  产生可用的窗口身份变化；
- 使用辅助功能 `AXPress` 自动点击侧栏：隔离验证中没有可靠触发任务导航，
  且不符合 QuotaView 只读展示边界；
- 扫描完整辅助功能树：会接触与功能无关的界面文字，不符合最小读取
  原则；
- 根据最近 Hook 事件猜测当前窗口任务：只能作为降级排序，不能代表用户
  当前查看的任务。

## MULTITASK-04. 数据与状态结构

现有单一 `CodexActivitySnapshot` 应扩展为多任务注册表，概念结构如下：

```text
TaskRegistry
└─ sessionHash → TaskState
   ├─ latestSnapshot
   ├─ resolvedThreadTitle
   ├─ workspaceName
   ├─ latestEventAt
   ├─ lifecycleRevision
   ├─ compactDeadline
   └─ hiddenDeadline

CurrentTaskResolver
├─ Codex 前台应用状态
├─ 当前标准窗口
├─ 主内容任务标题
└─ App Server 线程匹配结果

PrimaryTaskArbiter
├─ 用户当前查看的高置信度任务
├─ 自动优先级降级结果
└─ 上一次稳定主任务

TaskClusterRenderState
├─ primaryTask
├─ railTasks
├─ totalTaskCount
├─ attentionTaskCount
└─ islandPresentation
```

每个任务独立执行旧事件过滤与 `20 / 120` 秒生命周期。任何一个任务的
计时器、`SessionEnd` 或标题解析失败都不能覆盖、取消或隐藏其他任务。

## MULTITASK-05. 主任务选择规则

主任务选择分为“用户焦点模式”和“自动降级模式”。

### 用户焦点模式

满足以下全部条件时，当前 Codex 任务直接成为主任务：

1. Codex 为当前前台应用；
2. 当前标准窗口可用；
3. 主内容区任务标题可用；
4. 标题与已知 App Server 线程能够唯一、高置信度匹配；
5. 匹配线程存在于任务注册表，或能够建立新的可信任务状态。

用户焦点模式优先于普通后台事件。用户切换任务后，主任务随标题确认
结果切换；用户离开 Codex 前往终端、浏览器、Xcode 或其他应用时，保持
最后一个稳定主任务，不立即跳转到最近产生事件的后台任务。

### 自动降级模式

未授权辅助功能、Codex 不在前台、标题不可用、标题重名或匹配失败时，按
以下优先级选择主任务：

1. `awaitingConfirmation`；
2. `error`；
3. `working` / `compactingContext` / `thinking`；
4. 仍在展示周期内的 `completed`；
5. `standby`。

同级任务按最近可信事件排序。自动降级切换应保留短暂稳定期，避免并行
Hook 高频事件导致主任务连续跳动。

### 后台注意状态

当用户焦点模式已经确定主任务时，后台任务进入待确认或失败状态不能
强制抢占主岛。主岛右侧任务列表必须通过状态色、任务名称和注意数量
表达该事件。

当 Codex 不在前台或当前任务无法识别时，待确认和失败可以按照自动优先级
成为主任务。

## MULTITASK-06. 最大态布局

### 单任务

只有一个可见任务时完全复用现有状态尺寸与三行布局，不显示背层卡片，
不因为未来多任务能力改变现有留白、字体、球体或截断规则。

### 多任务

存在两个及以上可见任务时进入多任务最大态：

- 继续使用单一承载 `NSPanel` 和单一主任务 Metal 渲染器；
- 多任务最大态固定为 `496 × 152 pt`，任务数变化不扩大承载窗口；
- 主岛内部继续使用右侧 `144 pt` 任务列表；左右区域之间不绘制竖向
  分隔线，只通过主内容尾部与任务列开头的自然留白建立层级；
- 右侧新增的 `16 pt` 从左侧主内容区重新分配，外层 `496 × 152 pt` 尺寸
  保持不变；左侧三行文字继续保持单行显示和尾部截断；
- 主岛继续显示 Metal 球、任务标题、状态标题、操作文案和任务列表；
- 任务列表是固定三行的有序视窗，不得将溢出任务交替替换到某一行；
- 任务列顶部、底部和左侧使用 `12 pt` 安全边距，最大态右侧内容边距加倍
  为 `24 pt`；顶部标题、三行视窗和底部提示之间使用一致的 `8 pt`
  分区间距；
- 三行任务采用 `20 pt` 行高和 `23 pt` 步进；底部“前 N / 后 N”位于独立
  `12 pt` 高提示区，不得贴近岛的下边缘；
- 任务超过三项时，顶部按“任务、任务计数器”的顺序组成居中标题组，
  两者统一使用 `10.5 pt` 字号、固定间距 `6 pt`；顶部、任务列表和底部
  提示分别保持中间对齐；
- 任务为一至三项时不显示顶部标题组和底部提示，任务行按实际数量组成
  独立列表模块并在右侧区域垂直居中；
- 当前任务位于前三项时显示 `1–3`；切换到第四项时整列滚动为 `2–4`，
  第四项稳定显示在底行；
- 被视窗隐藏的任务数量和方向使用“前 N / 后 N”表达；
- 完整任务列表如后续需要，应进入现有菜单栏面板，不能无限增加灵动岛
  高度。

`496 × 152 pt` 与 `144 pt` 是当前 Demo 冻结值，不是未经视觉验收即可
进入生产的最终尺寸。视觉验收可以微调左右留白、阴影、任务列表反馈和
Metal 状态过渡，但不得恢复竖向分隔线、增加常驻背层卡片、移除主岛右侧
任务列表或改回右侧独立小岛。

## MULTITASK-07. 紧凑态与整体显隐

多任务紧凑态可见胶囊高度固定为 `52 pt`，宽度随状态、任务标题和任务总数
自适应；承载投影的面板在可见胶囊四周各保留 `10 pt`。

紧凑态只显示：

- 左侧 `28 pt` Metal 球，保持 `12 pt` 左侧留白；
- 当前主任务状态按实际文字宽度占位，完整显示且不参与滚动；
- 状态后的独立任务标题视窗在 `44–128 pt` 之间自适应；
- 标题未溢出时静态显示，溢出时才启用循环跑马灯；
- 跑马灯左右边缘使用渐隐遮罩，循环副本之间保留 `28 pt` 间距；
- 右侧固定 `54 pt` 区域完整显示“共 N 项”，不再用注意数量替代总数。

右侧“共 N 项”同时是紧凑态的任务详情入口：点击计数区后，
灵动岛使用既有尺寸过渡切换到最大态。命中区覆盖整个右侧计数
模块，而不是只命中文字墨迹；指针显示为点击手势，并提供 VoiceOver
“展开任务详情”操作。单任务时不显示计数区，也不创建隐形命中区。

紧凑态通常只在任务完成后出现，因此状态与任务标题必须拆分：八种状态
（包括“正在压缩上下文”）均保持完整，但状态区域不得按照最长文案预留
固定空白；只有超出最大视窗宽度的标题参与跑马灯。
开启 Reduce Motion 时停止跑马灯，并将溢出标题回退为静态尾部省略。

整体显隐规则：

- 任意任务处于 `thinking`、`working`、`compactingContext` 或
  `awaitingConfirmation` 时保持最大态；
- 任意任务刚进入完成后的 20 秒最大态阶段时保持最大态；
- 所有保留任务均进入紧凑阶段后，整体才进入紧凑态；
- 所有任务均完成各自 120 秒展示周期或收到 `SessionEnd` 后才隐藏；
- `SessionEnd` 只移除对应 `sessionHash`；
- 被移除任务是主任务时，立即选择下一个可信任务；
- 新事件只重新展开对应任务，并由主任务选择规则决定是否切换主岛。

## MULTITASK-08. 任务切换反馈

任务切换不再动画化完整岛卡片：

- 承载窗口的位置和尺寸保持稳定；
- 主岛卡片不位移、不旋转、不缩放、不翻转，也不整体淡入淡出；
- 主任务标题、状态、操作文案与任务列表选中态在同一次状态更新中同步；
- Metal 球保持同一渲染实例，并同步过渡到新任务状态；
- 不创建第二个 `NSPanel` 交叉淡入；
- 任务列表保持原始顺序，并以连续三项为一个可见窗口；
- 超过三项时整列按 `23 pt` 行步进纵向移动，禁止只替换末行内容；
- 任务行的选中强调使用约 `0.5 s` 滚轮式 ease 动效，边缘行轻微
  变淡和缩小；整列位移与玻璃形变共用约 `0.8 s`；
- 未选中任务在统一标记槽位显示 `5 × 5 pt` 状态圆点；选中任务不再显示
  状态圆点，而是在同一位置显示 `5 × 12 pt`、`2.5 pt` 圆角的选中线；
- 取消任务行左侧独立选中线，任务名称起点从 `32 pt` 前移至 `24 pt`，
  释放的 `8 pt` 全部用于任务文字，不改变 `144 pt` 任务列表宽度和最大态
  外轮廓；
- 选中标记是同一个连续对象：从原任务的 `5 × 12 pt` 选中线向右液化
  展开为 `116 × 20 pt`、`6 pt` 圆角的瞬时玻璃矩形，在 `144 pt` 任务列
  内保留左侧 `4 pt`，右边缘与最大态任务内容的 `24 pt` 安全边距对齐，
  刚好完整包裹任务选项；目标任务的 `5 × 5 pt` 状态圆点同步消失，玻璃在
  岛面之上、任务文字与圆点之下纵向移动到目标任务后，再收缩为新的
  `5 × 12 pt` 选中线；
- 任务文字与圆点必须位于独立清晰前景层，不作为 `NSGlassEffectView` 的
  背景采样内容，避免系统折射和散射令小字号任务名失焦；
- macOS 26 使用 Apple 原生 `NSGlassEffectView`、`clear` 风格与 `10%`
  状态色 tint；macOS 14–15 使用 `NSVisualEffectView` 的
  `underWindowBackground` 材质回退；
- 选中线到玻璃再回到选中线的总时长约 `0.8 s`，玻璃中段移动与任务列
  滚动同步；任务文字和状态点始终清晰绘制在玻璃之上；
- 视窗滚动而选中槽位不变时，清晰任务前景从玻璃上方滚过；
- 右侧未选中任务仅在状态为 `thinking` 或 `working` 时，任务名使用
  与主内容底部当前操作文字相同的 Codex 流光、渐变和 `2.6 s`
  循环节奏；选中成主任务后立即停止；
- 标题识别必须先达到高置信度，再更新主任务；
- 高频焦点变化应合并，只呈现最后一个稳定任务。

开启 Reduce Motion 后：

- 取消任务列表滚动、选中指示器移动和行缩放；
- 停止紧凑态标题跑马灯，使用静态尾部省略；
- 停止右侧未选中活动任务名的流光；
- 主任务文字直接更新；
- 保留任务列表状态和完整语义。

## MULTITASK-09. 辅助功能权限与隐私边界

“跟随当前 Codex 任务”需要用户自愿授予 macOS 辅助功能权限。

权限请求不得出现在首次启动或首次连接 Codex 的必经流程。只有检测到两个
及以上并行任务，或用户在设置中主动开启“跟随 Codex 窗口”时，才解释
价值并触发系统授权。

正式实现必须满足以下最小读取规则：

- 只面向 Bundle ID `com.openai.codex`；
- 只确定前台或聚焦的标准窗口；
- 只读取主内容标题位置的控件角色与标题；
- 只将标题与已经通过 App Server 获得的线程名称进行内存内比较；
- AX 读取值不得写入日志、持久化文件、诊断信息、Telemetry 或崩溃附注；
- 不读取侧栏完整列表；
- 不遍历或保存完整辅助功能树；
- 不读取提示词、回复、命令、参数、工具输出、预览或输入框内容；
- 不调用 `AXPress`、键盘注入、鼠标注入或其他 UI 控制操作；
- 不使用辅助功能权限打开、切换、关闭或操作 Codex 任务；
- 权限被拒绝或撤销后立即回退到自动降级模式，既有 Hook 状态继续可用。

设置说明必须明确：

> QuotaView 只读取 Codex 当前任务标题，用于让灵动岛跟随你正在查看的
> 任务；不会读取提示词、回复、命令或工具内容，也不会操作 Codex。

## MULTITASK-10. 匹配置信度与降级

任务标题不是业务主键，只是从当前窗口定位到 `sessionHash` 的临时桥梁。

允许切换主任务的高置信度条件：

- 标题非空且长度在既有安全限制内；
- App Server 返回一个精确标题匹配；或
- 标题与工作区组合只对应一个活动线程；
- 匹配线程能够与 Hook 任务注册表建立一致身份。

以下情况禁止自动切换：

- 相同工作区存在两个同名活动任务；
- 标题仍为通用值 `ChatGPT`、`Codex` 或空值；
- Codex 更新后主标题控件角色或位置失效；
- App Server 暂时不可用；
- 标题与 Hook 任务注册表互相矛盾；
- 辅助功能权限不可用。

禁止切换时保持上一个稳定主任务，并在内部记录不包含标题正文的粗粒度
诊断代码。不得把匹配失败解释为任务失败、连接失败或额度不可用。

## MULTITASK-11. 可访问性

- 多任务最大态作为一个辅助功能组，标签先报告任务总数与当前主任务；
- 主任务标签继续包含任务名、状态和当前操作；
- 后台待确认或失败状态必须通过文本数量表达，不能只依赖状态色；
- VoiceOver 只主动播报主任务切换、新的待确认和可靠失败；
- 普通后台工具事件不得反复打断 VoiceOver；
- Reduce Motion 使用静态切换；
- Increase Contrast 下主岛边界和任务列表文字必须仍可辨认；
- 标题截断只影响视觉显示，完整任务名称应保留在辅助功能标签中。

## MULTITASK-12. 实现阶段

后续生产实现按以下顺序执行，不得从动画或视觉列表开始倒推数据模型：

1. 将单一 Store 改为按 `sessionHash` 隔离的任务注册表；
2. 完成跨任务旧事件过滤、独立标题解析和独立收起计时；
3. 建立主任务仲裁器与无权限自动降级模式；
4. 建立可选辅助功能授权与最小化当前标题解析器；
5. 完成唯一匹配、重名、失配、权限撤销和 Codex 更新降级；
6. 建立多任务渲染模型；
7. 实现固定单一主岛与右侧任务列表；
8. 实现直接任务切换、任务列滚轮、紧凑态跑马灯、Metal 状态过渡和
   Reduce Motion；
9. 补充本地化、VoiceOver 和设置说明；
10. 完成自动化测试、Release 构建与产品所有者视觉验收。

## MULTITASK-13. 验证矩阵

自动化测试至少覆盖：

- 两个及三个会话的 Hook 事件交错；
- 某个会话的旧事件不能覆盖该会话新状态；
- 一个会话的事件不能取消另一个会话的收起计时；
- `SessionEnd` 只移除对应任务；
- 主任务结束后正确提升下一个任务；
- 用户焦点任务优先于普通后台事件；
- 后台待确认只更新主岛任务列表提醒；
- Codex 不在前台时自动优先级正确；
- 标题唯一匹配、同名冲突、空标题和 App Server 不可用；
- 辅助功能未授权、拒绝和运行中撤销；
- 单任务布局与当前生产版本一致；
- 两个、三个、四个及超过四个任务的 `496 × 152 pt` 固定单岛布局；
- 任务列从 `1–3` 到 `2–4` 的连续有序窗口，不得交替替换末行；
- 任务列顶部、底部、左侧 `12 pt` 与右侧 `24 pt` 边距、`8 pt` 分区间距和
  独立底部提示区；
- 一至三项任务隐藏分页头尾并垂直居中，第四项出现后才显示居中的

- 点击紧凑态“共 N 项”后展开到最大态，设置面板模式同步更新；

- Reduce Motion、Increase Contrast 与 VoiceOver；
- 生产日志、诊断文件和崩溃附注不包含 AX 任务标题；

## MULTITASK-14. 变更控制

以下内容已经冻结，后续实现不得自行改变：

- 多任务承载在固定尺寸的单一 `NSPanel` 内，不创建多个系统窗口；
- 单任务保持现有设计；
- 多任务采用一张固定外轮廓的完整主岛，不显示常驻背层卡片；
- 主岛内部保留右侧任务列表；
- 最大态左右区域只用留白分隔，不恢复竖向分隔线；
- 紧凑态必须拆分自适应完整状态、可滚动标题和固定宽度总数标签；
- 任务列表必须保持输入顺序，并通过连续窗口整体滚动显示溢出任务；
- 用户当前查看的 Codex 任务优先成为主任务；
- 后台普通事件不抢占用户主任务；
- 任务切换不得动画化完整岛卡片或承载 `NSPanel`；
- 焦点识别必须使用可选权限并提供完整降级；
- 只读取当前任务标题，不扫描任务内容；
- 不通过辅助功能控制 Codex；
- 不能高置信度匹配时不切换。

若后续需要改变上述任一项，必须先取得产品所有者明确确认，并同步更新
本文与现有 Codex 灵动岛产品文档。内部尺寸微调仍需遵守 QuotaView 既有
设计令牌和产品所有者视觉验收边界。
