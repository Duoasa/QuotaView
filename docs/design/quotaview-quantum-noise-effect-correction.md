# QuotaView 量子噪点效果修正规格

> Spec ID：`QV-PRODUCT-ACTIVITY-ISLAND-QUANTUM-NOISE-009`
>
> 状态：`Accepted / Verifying`
>
> 日期：2026-08-30
>
> 生产基线：`0.4.2 Build 1`；目标版本：`0.4.3 Build 1` / Sparkle 内部序号 `15`

## 用户结果

原“液滴涌动 / Drop Field”更名为“量子噪点 / Quantum Noise”。Codex 状态
切换时只平滑过渡颜色与亮度，微粒场不再因状态运动参数变化而整体上下位移；
常规动画提高平均粒子不透明度并增加更明显、彼此错开的星点闪灭；完成段在保持克制峰值亮度的同时，
让更多中等密度粒子参与高亮。

## 已确认根因

量子噪点与状态烟雾共用完整状态 Profile，颜色插值同时改变 `turbulence`、
`fieldSpeed` 等运动参数。旧 shader 又以累计 `fieldTime` 乘动态
`turbulence` 计算纵向偏移，导致新系数追溯作用于全部历史时间；像素单元的
`floor` 与 cell seed 进一步把连续偏移放大为整行微粒重排。

## Requirement

| ID | Requirement |
|---|---|
| `QUANTUM-NOISE-01` | 保留持久化枚举与 raw value `dropField`，只把用户可见名称改为“量子噪点 / Quantum Noise”，已有偏好无需迁移 |
| `QUANTUM-NOISE-02` | 九种 Codex 状态继续复用状态烟雾的颜色语义；颜色切换使用既有平滑插值，但不得改变量子噪点的采样位置。由于离散粒子覆盖率远低于烟雾，`compactingContext` 允许仅提高同一冷灰白语义的亮度以补偿可见性 |
| `QUANTUM-NOISE-03` | 量子噪点使用独立、连续、固定速率的效果时钟；纵向相位不得再由累计时间乘状态相关参数计算，活动状态之间切换不重置时钟 |
| `QUANTUM-NOISE-04` | 单元保持 `2.35` 渲染像素的细密密度；星点闪灭使用 cell seed 错开相位与速率，最低亮度明显低于旧版但不整片熄灭 |
| `QUANTUM-NOISE-05` | 量子噪点完成高亮峰值保持 `18%`，完成段密度指数由通用 `3.0` 降为 `1.5`，使更多中等密度粒子短暂高亮；晶钻前沿和液态涌浪保持 `14%` 与 `3.0`，状态烟雾保持既有完成反馈 |
| `QUANTUM-NOISE-06` | Reduce Motion 不推进独立效果时钟，也不播放完成脉冲；任务进度、生命周期、岛体几何和其他三种效果不得改变 |
| `QUANTUM-NOISE-07` | 进度条模式左侧任务标题使用不透明 `88%` 灰，操作状态使用不透明 `76%` 灰，使两行与右侧纯白主状态形成层级；操作状态流光保持既有宽度与 `2.6 s` 节奏，中心为 `100%` 白、两侧为 `24%` 白；只允许展开/收起过程调整视图透明度，不新增文字阴影、底板或发光，不改变状态圆点语义 |
| `QUANTUM-NOISE-08` | 量子噪点的压缩上下文色阶使用冷灰白 `0.50/0.53/0.57`、`0.68/0.72/0.77`、`0.88/0.92/0.98`；只替换颜色，不改变压缩态速度、扰动、扩散、能量、透明度曲线或独立效果相位，其他三种效果继续使用标准状态烟雾 Profile |
| `QUANTUM-NOISE-09` | 保留量子噪点既有 `0.22 + 0.62 + 0.16` 闪灭曲线，并将粒子不透明度统一提高 `10%`、上限钳制为 `1.0`；不得改变闪灭速率、采样相位、完成反馈或其他效果的不透明度 |

## 非目标

- 不改变 `stateSmoke`、`diamondFront`、`sloshFlow` 的运动语言；
- 不建立新纹理、网络读取、文件读取或新的持久化字段；
- 本轮不封包、不发布、不更新 appcast。

## 20 秒单任务测试范例

范例 ID：`QUANTUM-NOISE-MANUAL-20S-01`。

前置条件：应用使用进度条灵动岛与量子噪点效果，Reduce Motion 关闭；测试
只使用一个真实 Codex 用户任务，不调用 `update_plan`，不创建步骤计数器，
不注入 `Stop`、`SessionEnd` 或其他 Hook 事件，也不使用手动停止。

建议时序：

1. `0–4 s`：分析请求，观察真实 `thinking` 状态与起始颜色；
2. `4–10 s`：执行一次只读本地工具操作，观察 `working` 状态；
3. `10–16 s`：检查工具结果并执行第二次只读核对，使真实状态在
   `thinking / working` 之间切换；
4. `16–20 s`：完成最终一致性检查并组织答复；约 `20 s` 时正常结束本轮，
   只允许 Codex turn 的真实 `Stop` 触发完成态。

验收点：测试期间灵动岛连续可见，中间工具结束不得触发完成动画；状态颜色
平滑切换且量子噪点不得整体上下位移；星点保持错峰闪灭；真实 `Stop` 后进度
只走满一次，并播放一次 `18%` 量子噪点完成高亮；高亮应覆盖更多中等密度
粒子但不能把整片背景同时提亮，随后按用户设置收起或隐藏。
若测试中自然发生 `permissionRequest` 或上下文压缩，可同时观察
`awaitingConfirmation` 或 `compactingContext`，但不得为了覆盖状态而伪造事件。

记录边界：自动化和日志只能证明事件顺序与单次完成；颜色、位移、闪灭和
亮度结论必须由产品所有者观察后记录，不得由执行者自行标记视觉通过。
