# QuotaView 0.3.4 用量概览扩展规格

> 文档编号：`QV-PRODUCT-USAGE-OVERVIEW-002`
>
> 文档类型：SDD 产品功能规格（Product Feature Specification）
>
> 规格状态：`Accepted`
>
> 交付状态：`Verifying`（Build 3 本地门禁通过，等待产品验收）
>
> 目标版本：QuotaView `0.3.4 (Build 3)`
>
> 更新日期：2026-08-11

## USAGE-OVERVIEW-00. 范围

本迭代扩展状态栏面板的用量概览，使主周期额度、Spark 周额度、30 日
Token 和成本估算可以在同一数据刷新与设置体系中独立呈现。实现继续使用
现有 Codex App Server，不增加账户写操作、OAuth、网页抓取、Keychain、
新凭据或新权限。

`0.3.4 Build 1` 保留为已通过本地验证与 Spark 局部产品验收的开发基线；
Build 2 在该基线上调整 Token 活动范围和每日桶时间语义。产品所有者在
Build 2 视觉检查后明确：半年只限制可展示历史的上限，不应移除原有连续
日期格与左上占位格；Build 3 按该澄清恢复完整 `16 × N` 网格。

非目标：

- 不改变 `0.3.3 Build 3` 已发布 Token 活动图表的范围、网格或历史事实；
- 不把 `0.3.2 Preview 1` 的多任务灵动岛迁入稳定源码；
- 不接入真实额度重置消费接口；
- 不把成本估算描述为账单、实际消费或 OpenAI 官方结算结果；
- 不为缺失、异常或可选 Spark / 指标数据伪造 `0`、`0%`；隐藏的可选区域
  不保留空白高度。Token 活动的不可用日期格与行首补齐格只遵循
  `USAGE-OVERVIEW-10`，不得解释为真实零用量。

## USAGE-OVERVIEW-01. 主周期额度与重置信息

1. 主额度标题保持“本周期剩余” / `Period Remaining`；
2. 订阅方案继续显示在主额度右上角，并使用现有官方名称归一规则；
3. 下次重置时间合并到主额度底部左侧，字体、字号和颜色与底部右侧
   “已使用”一致；
4. 面板设置不再提供独立的“下次重置”开关，主额度可见时重置信息随之
   可见；
5. 菜单栏的“下次重置倒计时”仍是独立设置，不受本条影响；
6. 数据不可用时沿用破折号和不可用语义，不显示虚假零值。

## USAGE-OVERVIEW-02. Spark 数据建模

1. 继续调用现有 `account/rateLimits/read`，不得为 Spark 新增网络请求；
2. `rateLimitsByLimitId["codex"]` 继续映射主周期额度；
3. `rateLimitsByLimitId["codex_bengalfox"]` 的 `primary` 窗口映射为独立
   Spark `RateWindow`，稳定实体 ID 为 `codex_bengalfox`；
4. Spark 使用自己的已用百分比、剩余百分比、周期长度和重置时间；
5. 百分比必须位于 `0...100`；Spark 缺失、窗口缺失或百分比越界时只忽略
   Spark，不得使主周期额度失败；
6. Spark 可选数据不得写入主额度指标，也不得修改连接状态语义。

## USAGE-OVERVIEW-03. Spark 视觉与显示规则

1. Spark 位于主周期额度正下方，面板项 ID 固定为
   `spark-quota-summary`；
2. 标题使用“Spark 周额度” / `Spark Weekly Quota`，剩余百分比与标题在
   同一行，百分比使用 Semibold，形成与主额度大号 Hero 数值的区分；
3. Spark 区域固定高 `82 pt`，水平内边距 `16 pt`、垂直内边距 `12 pt`，
   内容使用 `9 pt` 垂直节奏；
4. 进度条复用现有 `8 pt` 高度、分段几何、描边、间隔与辅助功能语义；
5. Spark 进度条只使用固定中性色。深色外观剩余 / 已用分别使用白色
   `88% / 30%`，浅色外观分别使用黑色 `62% / 18%`；不得按额度风险切换
   绿色、黄色或红色；
6. 底部左侧显示下次重置，右侧显示已使用百分比；
7. Spark 不重复显示订阅方案；
8. 只有设置开启、当前 Codex 状态有效且 Spark 窗口存在时才显示；隐藏后
   不保留 `82 pt` 空白。

## USAGE-OVERVIEW-04. 30 日 Token

1. “30 日 Tokens” / `30-Day Tokens` 使用与成本估算相同的 UTC 三十日
   窗口：今天及之前二十九天；
2. 只汇总该窗口内 App Server 提供的官方每日用量桶；窗口外数据不参与；
3. 缺失日期不得补造 Token，用量完全不可用时显示破折号；
4. 数值继续使用现有紧凑 `K / M / B` 格式；
5. 设置开关默认为开启，持久化键为
   `preferences.panel.showThirtyDayTokens`。

## USAGE-OVERVIEW-05. 成本估算

1. 成本估算使用最近三十个 UTC 自然日的 Token 总量；
2. 当前 Build 使用 GPT-5.6 Sol 缓存输入参考价
   `$0.50 / 1,000,000 tokens`，计算为
   `tokens / 1,000,000 × 0.50`；
3. 标题为“成本估算（30 天）” / `Cost Estimate (30d)`，底部必须显示
   “估算值 · 非账单” / `Estimated · Not a bill`；
4. 图表固定三十个日期位置，柱高只表达当前窗口内相对估算值；缺失数据
   不得画成真实零值；
5. Hover 提供本地化日期和该日估算值，容器和每日位置提供辅助功能文本；
6. 底部右侧显示三十日窗口内最近一个有效日桶的估算值，并使用“最近一天” /
   `Latest day` 语义；不得把上一有效日桶改写成今天；
7. 完全没有可用日桶时周期总额、最近一天值和刻度显示破折号，不伪造
   `$0`；
8. 设置开关默认为开启，持久化键为
   `preferences.panel.showEstimatedCost`；
9. 参考价是本地估算常量。未来价格、模型或计费口径变化必须更新规格、
   文案、测试和 Build Number，不得静默修改。

## USAGE-OVERVIEW-06. 设置、顺序与请求需求

设置窗口的面板内容顺序与菜单顺序保持一致：

1. 周期用量概览；
2. Spark 周额度；
3. 成本估算图表；
4. Credits 余额；
5. 最近一天 Token；
6. 30 日 Token；
7. 累计 Token；
8. Token 活动图表；
9. 额度重置入口。

Spark 额度来自必需的 rate-limit 响应，不扩大 usage 请求需求。最近一天、
30 日、累计、Token 活动或成本估算任一项开启时，usage Demand 保持开启；
这五项全部关闭后才允许停止可选 usage 数据请求。

## USAGE-OVERVIEW-07. 面板尺寸、状态与辅助功能

1. 菜单宽度保持 `274 pt`，顶部锚点固定，所有可见内容只向下扩展；
2. Spark 显示时在计算高度中增加 `82 pt`，隐藏时立即移除该高度；
3. 成本估算区高 `176 pt`；指标行继续使用 `36 pt`；
4. 主额度保留风险色；Spark 和 Token / 成本量级图表不得把颜色解释为
   服务健康、连接状态或账单风险；
5. 所有可见文字、Tooltip、日期、倒计时和辅助功能文本必须支持简体中文与
   English 即时切换；
6. 数字变化保留 numeric transition；Reduce Motion、Increase Contrast 和
   VoiceOver 继续遵守现有面板规则；
7. 完整外观、语言和辅助功能交叉矩阵未被本次局部产品验收自动标记为通过。

## USAGE-OVERVIEW-10. Build 3 Token 活动半年上限与完整网格

1. Token 活动右上角第四个范围从“总计” / `All` 改为“半年” / `6M`；
2. 周、月和三个月继续使用原有连续 UTC 日期范围；半年范围从范围内最早的
   有效日桶开始，但不得早于结束日向前六个月的边界；没有有效历史桶时，
   半年范围沿用一个月空状态；
3. 从解析出的开始日到结束日必须为每个 UTC 自然日生成真实日期格。服务端
   缺失某日桶时，该日期格以统计不可用呈现，不得伪造成真实零用量；
4. 同一 UTC 日期的多个有效桶合并求和，窗口外桶与负数异常桶不参与；
5. 每行固定显示 `16` 个 `12 × 12 pt` 方格，总格数向上补齐为 `16` 的
   整数倍；真实日期按时间升序从右下角对齐，不足部分只允许用左上虚线
   占位格补齐；
6. 占位格必须与真实日期格可区分，不响应 Hover，并从辅助功能树隐藏；
7. 旧偏好值 `total` 必须无损迁移为新的半年范围，不能导致设置重置或崩溃。

## USAGE-OVERVIEW-11. 每日桶日期一致性

1. “最近一天 Tokens”与 Token 活动、30 日 Tokens、成本估算必须消费同一
   组官方每日桶，并保留每个桶的真实 UTC 日期；
2. 列表不得把“最近一个有效日桶”无条件称为“今日 Tokens”；
3. 服务端尚未返回今天的日桶时，不得复制最近一天的数值来填充今天；Token
   活动的今天日期格显示统计不可用，成本图今天位置保持无数据，最近一天
   摘要仍可显示最近有效桶的真实数值；
4. 服务端返回今天的有效桶后，列表、Token 活动和成本估算必须在同一次
   快照中一致显示该桶；
5. 自动化必须覆盖“最新桶不是今天”和“最新桶就是今天”两种情况。

## USAGE-OVERVIEW-09. 变更与发布控制

- 当前公开 Latest 保持 `0.3.3 Build 3`，不得在正式发布门禁完成前将
  `0.3.4 Build 3` 或继承本范围的开发候选写成公开 Release；
- 本规格最终 `0.3.4` 开发迭代使用 Build 3，并已由 `0.3.5 Build 4` 候选
  继承；从 Build 4 起编号全局递增，不得因 Marketing Version 变化而重置；
- 每次 Build 更新必须同步 App、Widget、兼容 Info.plist、Handoff 与 SDD
  索引；
- 修改 Spark limit ID、隐藏条件、中性颜色、成本参考价、三十日边界或
  “非账单”语义时，必须更新本规格和对应测试；
- 不得引入 OAuth、网页抓取、Keychain、新权限、真实重置消费或调试数据
  注入来实现本规格。
