# QuotaView SDD 开发流程

文档编号：`QV-SDD-PROCESS-001` · 状态：`Accepted`

规格保存目标、约束和验收证据。按任务选取需要的部分，不要求每次经历完整
产品生命周期。读取入口见 [AGENTS.md](../../AGENTS.md)，当前工作与规格分别
见 [Handoff](../../HANDOFF.md) 和[注册表](README.md)。

## 任务范围与完成条件

| 任务 | 最小规格工作 | 本次完成条件 |
|---|---|---|
| 拼写、链接、无行为影响的文档修复 | `Spec impact: None`；不新增 Spec | 修改与引用正确，diff 检查通过 |
| 已有功能局部修复 | 复用 Requirement；目标改变时更新该段 | 请求行为修复，相关验证完成，剩余验收如实记录 |
| 新功能或新的架构边界 | 唯一 Spec ID、目标/非目标、不变量、状态/失败语义、验收条件 | 已授权范围实现，相关证据与规格一致 |
| Prototype | 验证的问题及生产隔离边界 | 可使用的原型与真实结论，不宣称生产完成 |
| 文档体系维护 | 修改既有流程或索引编号，保留产品交付状态 | 路由、链接、授权一致，历史证据可追溯 |
| 发布或撤回 | 精确版本与渠道，按[发布规则](../workflow/RELEASE.md) | 获准渠道操作与最终资产验证完成，记录同步 |

较大规格只增加确实影响决策的架构、迁移、资源预算、阶段或回滚内容。
局部修复无需补齐整套模板；测试和文档数量不是完成标准。

## 授权与持续执行

- 用户明确要求实施或修复时，记录已有授权并持续完成相关规格、实现、验证，
  不把“先写规格”解释为写完后必须再次询问能否实施。
- 仅接受设计或讨论不自动授权生产修改。产品方向、Prototype 迁入、版本身份
  和发布保持对应边界；同一会话已有授权不重复请求。
- 阶段出口是检查点。除非用户要求阶段审核，或下一步依赖新决策/权限，否则
  继续到本次任务终点，不在第一版实现后默认交回。
- 不确定点先用相关代码、文档、只读检查或隔离验证解决；仍影响正确性时才
  停下依赖它的操作。说明具体阻塞，并完成可独立推进的工作。
- 视觉、交互和辅助功能体验由用户判断。等待这些判断时继续完成不依赖它们
  的修复、必要验证和记录；自动化、构建和 Demo 不能替代人工验收。

## 状态词汇

规格、实施授权、交付阶段和人工验收是独立事实。规格状态使用
`Draft / Review / Accepted / Superseded / Archived`；`Accepted` 表示设计接受，
实施授权以用户实际请求为准。

| 交付状态 | 含义 |
|---|---|
| `Discovery` | 仍在确认问题、边界或关键决策 |
| `Prototype` | 隔离探索，未进入生产 |
| `Planned` | 范围已定义，尚未开始 |
| `Implementing` | 正在落实已授权的生产实现 |
| `Verifying` | 实现已存在，仍有必要验证或人工验收 |
| `Complete` | 本次非发布任务结果及必要验证完成，不代表发布 |
| `Released` | 精确 tag、Release、资产及要求的回下载验证已发生 |
| `Superseded` | 交付被后续规格接替，保留原记录和链接 |

这些状态无需逐项经过。已发布版本仍可有非阻断的实机验收待办；按场景分别
记录，不回写为“全部验收通过”。阻塞写明对象、原因和下一步，不伪造结果。

## 验证与维护

- 按[验证规则](../workflow/VALIDATION.md)选择能证明变更的检查。通过后仅因
  新改动、失败或未覆盖风险复验，不为“收尾”再全部运行。
- 目标变化更新 Requirement；证据变化更新对应证据。注册表只保存 ID、链接、
  状态和简短结论；Handoff 保存开发最新版、未完成工作和下一步，历史另存。
- 只有发布、撤回、Latest 或资产变化才改版本历史，并同步受影响的 Handoff、
  README 和渠道记录。普通文档维护不打包、不改产品版本。
- PR 说明问题、范围、Spec/Requirement 或无影响理由、验证和实际待验收项；
  无关的权限、发布和验收矩阵无需逐条填写。
