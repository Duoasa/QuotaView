# 品牌升级公告

Spec ID：`QV-BRAND-ANNOUNCEMENT-001` · `Review / Verifying` · 2026-10-29

## 目标与授权

用户要求先查看更新后首次启动的品牌升级公告，后续两个版本均能展示，暂不发布；本轮明确使用现有名称与 Logo。实现可在当前开发应用查看的原生弹窗与提醒策略，正式文案、目标版本及视觉仍待确认。

不涉及重新命名产品、更换图标、网络公告服务、appcast 改动或 Release 发布。现有 CodexBar 参考没有可直接沿用的公告方案；按用户“先用现在的”复用 QuotaView 既有窗口、资源与系统字体，不增加外部 UI 依赖。

## 界面与关闭语义

- 520 × 520 深色原生窗口，现有应用图标、品牌升级预告、两行标题与简短正文；一个“继续使用”主按钮。
- 关闭按钮、Escape、回车或主按钮关闭；正常关闭后才记为该版本已查看。崩溃或未确认即退出不提前消耗提醒。
- “设置 → 关于 → 品牌升级公告 → 查看”可重新打开；手动查看不消耗首次启动提醒。
- 中英文使用 AppCopy，标题具备标题语义，装饰图标不重复朗读；静态微光不产生持续动画。
- 外观参数见[界面规范](../design/QUOTAVIEW_UI_RULES.md#品牌升级公告2026-10-29086-build-10)。具体视觉与键盘、辅助功能体验由用户验收。

## 两个版本的展示规则

`BrandAnnouncementCampaign` 使用活动 ID 和明确的内部 `CFBundleVersion` 集合。启动时仅在正式身份、版本属于名单且本地尚未确认时弹出；回执存储在该活动的 UserDefaults 键下，内容为已查看的版本集合。

同一版本确认后重启不重复；升级到第二个指定版本再次显示。跳过第一个版本的用户安装第二个版本仍能看到；未配置版本不会自动显示。新安装指定版本也会展示。数据为本机记录，不提供跨设备同步。

当前 `releaseBuilds` 为空，正式自动弹窗未启用。发布前必须填写两个已确定的内部版本序号；不能把每个本地开发 Build 都当作一个发布版本，也不能使用活动级单一已读标记吞掉第二次提醒。
